# Самостоятельная запись тренером

Роль TRAINER создаёт занятия из рабочего места `/trainer` в браузере на телефоне и ПК. Существующая маршрутизация переводит тренера из `/schedule` в это рабочее место. Используется общая боковая шторка LessonDrawer; тренер закреплён по данным серверного рабочего места. Сохранение обновляет расписание без перезагрузки страницы. Telegram TMA использует отдельную авторизацию и отдельные API; эта задача изменяет браузерную CRM.

## Доступ и финансовая безопасность

- `POST /lessons`: TRAINER допускается только при FULL доступе к включённому SCHEDULE. Без привязанного trainerId — 403; чужой trainerId — 403. Отсутствующий trainerId подставляется сервером. ADMIN/MANAGER по-прежнему обязаны указать тренера.
- Контроллер и сервис независимо проверяют владельца расписания. Сервис отклоняет cost, pricePerPerson, prepaymentAmount и prepaymentMethod, включая нули и null. Цена определяется услугой на сервере; приём денег тренеру недоступен.
- Создание занятия, начисление по услуге, уведомления и CashAuditLog выполняются в существующей Serializable транзакции. Событие LESSON_CREATED_BY_TRAINER содержит actorId, actorName, lessonId и trainerId. Ошибка аудита отменяет создание.
- Ответ тренеру проходит trainerLessonView: без стоимости, платёжной истории и абонементных балансов. Клиенты чужих занятий остаются скрытыми. Обработка занятости поддерживает client=null.
- `POST /clients/quick`: доступен TRAINER при FULL SCHEDULE; возвращает только id, name, clientType и riderLevel. SanitizeRbacInterceptor сохраняется. Данные телефона принимаются, медицинские сведения и финансовые поля в ответ тренеру не попадают.
- Справочники services, arenas, horses, trainers доступны тренеру на чтение. Для services/arenas добавлена защита модулем SCHEDULE.
- Новый `GET /clients/:id/booking-memberships?serviceId=…&from=…&to=…` принимает UUID и ISO-время, возвращает исключительно id/title подходящих абонементов. Учитывает владельца/семейный доступ, услугу (включая совместимые старые абонементы без serviceId), активный статус, доступное занятие и весь интервал тренировки. Депозитные/постойные абонементы исключены. Полный финансовый каталог memberships не открывается тренеру.
- При создании занятия принадлежность абонемента проверяется повторно через canUseMembership внутри транзакции, с проверкой срока, статуса, типа и услуги. Существующий жизненный цикл списания посещения сохраняется.

## Проверки

Автоматические сценарии: `backend/test/trainer-booking.test.cjs`, обновлённый `backend/test/quick-clients.test.cjs`, `frontend/e2e/workspace.spec.ts`. Проверяются HTTP 201/403, изоляция ответа, финансовые поля, отсутствие профиля, FULL/READ_ONLY/HIDDEN, справочники, семейный доступ, срок/услуга абонемента и откат при ошибке аудита. Браузерный сценарий на 390/1440 px создаёт гостя, выбирает абонемент, повторяет сохранение после 409 и проверяет обновление сетки.

Проверки TypeScript, lint и build выполнены для backend и frontend. Полные результаты тестов: `docs/reports/trainer-booking-backend-tests.log`, `docs/reports/trainer-booking-frontend-tests.log`. Статический UI-аудит и сравнение с HEAD: `docs/reports/trainer-booking-premium-audit.json`, `docs/reports/trainer-booking-premium-comparison.json` — по 247 замечаний в исходной и изменённой версиях, новых типов замечаний нет; сканер ошибочно трактует Ant Design Form.Item и Select как HTML-теги.

Схема Prisma не менялась. Миграция и генерация Prisma Client не требуются. PostgreSQL-интеграционные тесты, пропускаемые штатным запуском без отдельной БД, не заменяют проверку на сервере.

Итог проверки: backend — 872 passed, 26 skipped, 0 failed; frontend — 191 passed; рабочее место — 18 E2E passed, расписание/оплаты — ещё 39 E2E passed. В существующем TMA-тесте обновлён устаревший селектор кнопки на «Общее расписание». В выборе абонемента Escape закрывает выпадающий список без закрытия шторки. Линтер backend содержит три ранее существовавших предупреждения; ошибок нет. Последний браузерный отчёт рабочего места: `docs/reports/trainer-booking-workspace-e2e.log`.
