# Персонал: специализация и доступ в CRM

Шаг 4, 25.11.2026.

## Поведение

`Trainer.allowIndividual`, `allowGroup`, `allowWalk`, `allowSpecial` хранят направления работы. По умолчанию все включены, в том числе для существующих тренеров. `StaffProfileDto` принимает их при создании и редактировании сотрудника; поля сохраняются в связанной карточке тренера внутри общей Serializable-транзакции. Отсутствующее поле при PATCH сохраняет прежнее значение. При выборе существующей карточки форма подставляет её направления.

`ToggleSettingRow` владеет четырьмя переключателями формы. `CrmAccessToggle` использует ту же плашку в форме и компактный Ant Design Switch в таблице. Отключение подтверждается через Ant Design App Modal, начальный фокус — «Отмена». В форме изменение вступает в силу после сохранения. READ_ONLY, собственная учётная запись и архивные сотрудники блокируют переключатель. Первичная выдача доступа требует email и временного пароля в карточке; повторное включение уже настроенной учётной записи сохраняет пароль.

Доступ управляется существующим `User.crmAccess`, независимо от `StaffProfile.isActive` и `Trainer.isActive`. Отключение входа не архивирует сотрудника, не закрывает смены и не изменяет ведомости. Изменение доступа увеличивает `tokenVersion`. Существующие `AuthService.validateUser`, `AuthService.refresh` и `JwtStrategy.validate` проверяют `crmAccess`; старые access/refresh JWT остаются отозванными после повторного включения доступа.

Сервер запрещает отключать собственный вход, архивировать себя и менять собственную роль. Последнему активному администратору нельзя отключить доступ, сменить роль или архивировать профиль. Проверка оставшихся администраторов выполняется в Serializable-транзакции с существующим повтором при конфликте сериализации. Менеджер не может изменять администратора.

`LessonDrawer` использует явное направление услуги и существующий fallback по названию/вместимости. `TriadBookingModal` использует сопоставление дисциплины. Общий `trainerServiceWarning` показывает мягкий Alert при явном `false`; отсутствующие поля старого API трактуются как разрешённые. Предупреждение не отключает сохранение.

## Миграция

На сервере необходимо применить `backend/prisma/migrations/20261125120000_trainer_service_directions/migration.sql` до запуска обновлённого backend. SQL использует `ADD COLUMN IF NOT EXISTS`, подходит для повторной прямой накатки через `psql`; финансовые таблицы и история не меняются. Локально выполнен `npx.cmd prisma generate`, Prisma Client 6.19.3 сгенерирован. Серверная БД в этой задаче не изменялась.
