# Роли и доступ

В системе используются существующие роли `ADMIN`, `MANAGER`, `TRAINER`. Администратор и менеджер сохраняют полный доступ к замене лошади. Тренер по умолчанию может заменять лошадь только в своём предстоящем запланированном занятии.

## Развёртывание

Перед запуском обновлённого backend нужна миграция `20261015190000_role_access_and_horse_history`. Она добавляет nullable-связь пользователя с тренером, таблицу прав и историю замен; существующие занятия и оплаты не изменяет.

Из каталога `backend`, с настроенным `DATABASE_URL`:

```powershell
npx.cmd prisma migrate deploy
npx.cmd prisma generate
npm.cmd run build
```

Затем перезапустить backend штатным способом. Для существующих учётных записей тренеров администратор открывает «Настройки → Роли и доступ» и связывает учётную запись с карточкой тренера из расписания. Связь уникальна; при её изменении `tokenVersion` увеличивается, и пользователь должен войти заново.

## Замена лошади

- `PATCH /api/bookings/:id/horse` принимает только `horseId` и необязательную `reason`. Автор берётся из проверенной сессии, а не из тела запроса.
- Проверка выполняется внутри serializable-транзакции. Для группового занятия используется текущий `lesson.trainerId`; для самостоятельного бронирования — `booking.trainerId`. Связь `User.trainerId` перечитывается из БД. При отсутствии связи допустимо совпадение с UUID самой учётной записи, как предусмотрено контрактом.
- Тренер с отключённым `horseReplaceOwn` либо с чужим занятием получает HTTP 403: «Вы можете заменять лошадей только в своих занятиях». Флаг `horseReplaceAny` никогда не выдаётся тренеру. Подбор `GET /api/bookings/:id/available-horses` защищён той же проверкой.
- История `BookingHorseChange` хранит `actorUserId`, прежнюю и новую лошадь, причину и серверное время. Запись истории и изменение бронирования атомарны. Оплаты и абонементы не затрагиваются.
- `GET /api/bookings/:id/horse-history` возвращает последние 100 замен; доступ — администратору, менеджеру или назначенному тренеру с правом замены. История доступна и после завершения занятия.

В интерфейсе кнопка скрыта для чужого занятия. Разрешение тренера появляется после загрузки серверной идентичности; при ошибке проверки оно не выдаётся. Те же условия используются в карточках обоих видов занятий и в списке проблемных записей.

## Управление правами

`GET /api/settings/access/me` возвращает текущие права и связь пользователя с тренером. `GET /api/settings/role-access` и `PATCH /api/settings/role-access/TRAINER` доступны только администратору. Изменение применяется ко всем тренерам. Права администратора и менеджера закреплены политикой и не отключаются через эту страницу.

| Право тренера | По умолчанию | Применение |
| --- | --- | --- |
| Замена в своих занятиях | Включено | Замена и подбор лошадей с проверкой владения |
| Замена в любых занятиях | Недоступно | Только администратор и менеджер |
| Просмотр журнала здоровья | Включено | Ветеринарный журнал, старый журнал здоровья и вложенные записи в карточке лошади |
| Редактирование журнала здоровья | Выключено | Создание, выполнение процедур и редактирование старого журнала; требует права просмотра. Удаление остаётся у администратора и менеджера |
| Финансовые отчёты | Выключено | `/financial-reports`, чтение `/api/payments/summary`; не выдаёт доступ к кассовым операциям |
| Раздел постоя | Включено | Просмотр денников и договоров; не выдаёт тренеру право изменять договоры |

Отключённые медицинские и постойные записи исключаются и из вложенных ответов карточек. Отдельные персональные поля по-прежнему скрываются от тренера. Сохранение прав и привязки требует подтверждения в интерфейсе; ошибки сохраняют черновик и отображаются рядом с формой.

## Проверки

- `backend/test/role-access.test.cjs`: владение, точный 403, ADMIN/MANAGER, отозванные права, защита подбора, HTTP-валидация, атомарность истории, реальные guards медицинского журнала/постоя/финансовых отчётов и маскирование вложенных данных.
- `backend/test/trainer-account-binding.test.cjs`: уникальность привязки, ограничения типа учётной записи, отзыв сессии.
- `backend/test/horse-replacement.postgres.test.cjs`: гонка замены, аудит и владение в PostgreSQL; запускается только при `RUN_TRIAD_TESTS=1` на изолированной локальной тестовой базе.
- `frontend/src/access.test.ts`, `frontend/e2e/role-access.spec.ts`: кнопки, роли, сохранение прав, привязка, mobile и доступ к отчёту. Браузерные тесты используют mock API; серверный HTTP-контракт проверяется отдельно.
