HTTP-тест проверяет POST /api/lessons с отсутствующим horseId, пустой строкой и null через реальный ValidationPipe. Тесты используют настоящий MembershipLedgerService с транзакционными mock-данными и проверяют отсутствие второго списания при завершении, отказ повторной оплаты и откат при ошибке признания выручки. PostgreSQL-проверка отдельно подтверждает списание, выручку, отсутствие повторного кассового прихода и возврат при отмене для запланированного и завершённого занятия.

Playwright проверяет создание обычного занятия без лошади и денег, маркер и колонку «Без лошади», оплату завершённого занятия через кассу с предвыбором клиента и записи, существующий абонемент, продажу нового и повторную привязку без второй продажи. Проверена ширина 390 и 1440 px; существующая регрессия также проверяет 768 и 1024 px.

Дополнительный общий audit_project.py --mode strict вернул 204 замечания, включая ложные срабатывания на Ant Design Form.Item и Select как на HTML form/select. Он не является прошедшей проверкой; его JSON сохранён локально в test-results/optional-horse-ui-audit.json. Проверки проекта, типов, сборок и браузера перечислены отдельно выше.

Для сервера требуется миграция 20261101120000_lesson_membership_payment. Автодеплой запускает штатный migrate deploy. Отдельное ограничение: постфактум-привязка не изменяет закрытый финансовый месяц; в этом случае транзакция откатывается. Продажа и привязка выполняются отдельно, при ошибке второй операции приобретённый абонемент сохраняется для безопасного повтора.
