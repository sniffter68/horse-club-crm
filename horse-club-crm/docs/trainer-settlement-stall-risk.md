# Тренер занятия и правила соседства денников

## Назначение тренера

`PATCH /lessons/:id/trainer` принимает обязательный UUID `trainerId`. Операция использует существующую проверку расписания и Serializable-транзакцию с повтором при конфликте. Изменяются и `Lesson.trainerId`, и `trainerId` всех участников занятия. Время, стоимость и способ оплаты сохраняются.

Общий серверный guard запрещает замену после любой оплаты, включая предоплату и списание с абонемента, а также после проведения. Ответ — 400 с сообщением «Тренер зафиксирован после оплаты. Сначала отмените или верните оплату занятия». Проверка действует также в API переноса и редактирования самостоятельного Booking. После обратной проводки у запланированного занятия без оплаты замена снова доступна; проведённые и отменённые занятия остаются закрыты для переноса.

`LessonTrainerField` используется в карточке, завершении занятия и кассе. Выбор сохраняется сразу; проведение оплаты блокируется на время сохранения. Предупреждение по специализации остаётся информационным. READ_ONLY показывает имя без селекта. Создание через LessonDrawer сохраняет текущий выбор тренера и поясняет, кому будет начисление.

Сохраняется существующая модель зарплаты: TrainerPayout формируется за период по проведённым занятиям, отобранным по актуальному `Lesson.trainerId`, с процентом выбранного тренера. Отдельная ведомость на каждый кассовый чек не создаётся. Финансовые операции и списание посещения продолжают использовать существующие транзакции и аудит.

## Денники

В `ClubSchedule` хранятся `stallRiskAdjacent = true` и `stallRiskOpposite = false`. API `GET/PATCH /settings/stall-risk` возвращает только эти флаги; PATCH принимает частичное обновление и проверяет модуль STABLES и права записи ADMIN/MANAGER.

Две плашки ToggleSettingRow доступны в списке `/stalls` и на карте `/stable`. После сохранения карта повторно получает серверные предупреждения. Ошибка сохраняет прежнее значение переключателя.

Одна функция `neighborhoodWarnings` учитывает флаги для старых координат и современной сетки, списка, карточки, карты, результата заселения и предпросмотра переселения. Смежность определяется общим краем, соседство напротив — через свободный проход; отключённая смежность не превращается в риск «напротив».

## Развёртывание

Перед запуском обновлённого backend применить `backend/prisma/migrations/20261126160000_stall_risk_settings/migration.sql`. SQL идемпотентен (`ADD COLUMN IF NOT EXISTS`) и пригоден для прямого запуска через psql. Prisma Client 6.19.3 сгенерирован локально. Миграция на сервере этой задачей не применялась.

## Проверки

Backend: смена тренера, оплата CASH/CARD, расчёт ведомости для нового и прежнего тренера, запрет замены; списание абонемента после замены; независимые флаги рядом/напротив для обеих моделей координат, сохранение false и валидация DTO.

Frontend: unit-тесты фиксации тренера, браузерные проверки замены и фиксации при завершении, выбора замены прямо в кассе, сохранения переключателей, обновления подсветки и ошибки сохранения. Основные сценарии проверены при ширине 1440 и 390 px.

Результаты команд находятся в `docs/reports/trainer-stall-*.log`. Дополнительный строгий статический UI-аудит выдал общие замечания репозитория, в том числе ошибочно классифицировал Ant Design Select в новом компоненте как native select. Для нового поля используется существующий Ant Design Select с label/aria-label; его открытие и выбор проверены браузером.
