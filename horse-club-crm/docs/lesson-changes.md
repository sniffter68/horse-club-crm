# Перенос и отмена занятий

Дата: 23.11.2026. Миграция Prisma не требуется.

`/trainer` и `/tma/trainer` используют общий `LessonActionsDrawer`: открытие из карточки с клавиатуры, детали клиента и оплаты, выбор новой даты/слота, подтверждение отмены с причиной. Владельцы контролов — Ant Design DatePicker ru_RU, Select, Drawer, App message/Alert и общая `entryDrawerTheme`. Ошибка сохраняет выбор; повторная отправка блокируется до завершения запроса; устаревшие загрузки отменяются; закрытие возвращает фокус. READ_ONLY блокирует действия. Занятое время показано недоступной кнопкой с причиной. Отметки проведения/неявки и отдельная замена лошади сохранены.

API персонала:

| Действие | CRM | Telegram |
| --- | --- | --- |
| Детали для управления | GET `/api/lessons/:id/management-details` | GET `/api/tma/lessons/:id/management-details` |
| Время для переноса | GET `/api/lessons/:id/reschedule-slots` | GET `/api/tma/lessons/:id/reschedule-slots` |
| Перенос | PATCH `/api/lessons/:id/scheduled-reschedule` | PATCH `/api/tma/lessons/:id/reschedule` |
| Отмена с причиной | PATCH `/api/lessons/:id/scheduled-cancel` | PATCH `/api/tma/lessons/:id/status` |

Дата — YYYY-MM-DD, время — HH:mm, Europe/Moscow. При переносе допустимы `horseId`, `trainerId`, `reason`. Смена лошади в группе выполняется отдельным существующим действием по участнику. Для нового одиночного назначения проверяются права замены лошади и сохраняется `BookingHorseChange` с исполнителем.

ADMIN имеет полный доступ. Сотрудник с FULL-доступом к SCHEDULE может управлять клубными занятиями. Для TRAINER используются существующие `lessonCreateOwn` / `lessonCreateAny`: собственное расписание / управление чужим. Переназначение тренера проверяет обе стороны. Смена лошади дополнительно использует `horseReplaceOwn` / `horseReplaceAny`. Внутри транзакции повторно проверяются права, а для Telegram — актуальность привязки сотрудника. Телефон и оплата выдаются только после проверки права управления конкретным занятием.

Перенос выполняется в Serializable-транзакции с повтором конфликтов сериализации. Сохраняются длительность, участники, membershipId, журнал списаний и оплата. Время, тренер и площадка синхронизируются в Lesson и Booking; смена времени сбрасывает подтверждения. BookingRulesService проверяет клиента, вместимость тренера и манежа, статус/архив лошади, отдых и суточную нагрузку по меньшему из двух действующих минутных лимитов. Предпросмотр слотов использует тот же валидатор без блокировок; сохранение заново проверяет ресурсы с блокировками.

Отмена разрешена только для SCHEDULED, требует причины и использует существующий возврат посещения в LessonsService. Денежная оплата блокирует отмену через кабинет тренера/TMA сообщением «Для возврата оплаты откройте полную CRM». Кассовый сценарий администратора в полной CRM сохранён. Уведомления Telegram/VK клиентам и Telegram администраторам ставятся в очередь в той же транзакции. Перенос содержит старое и новое московское время, отмена — причину.

Клиентский TMA использует inline-компонент `ClientReschedule`, системные date/select, ошибки рядом с формой и повторную загрузку слотов. Маршруты GET `/api/tma/client/lessons/:id/reschedule-slots` и POST `/api/tma/client/lessons/:id/reschedule` доступны только владельцу записи; контроллер также поддерживает запрошенный алиас `/api/telegram-bot/client/lessons/:id/reschedule`. Клиент не задаёт лошадь, тренера, длительность или оплату. Срок переноса берётся из `Service.cancellationWindowHours`; для старой записи без услуги — 24 часа. Доступны ближайшие 30 дней. `canReschedule` вычисляется одинаково для главного экрана и истории записей. Индивидуальное занятие переносится самостоятельно; перенос одного участия в группе требует администратора, чтобы не менять время других клиентов и финансовую привязку их посещений.

Лёгкий клиентский bundle сохраняет React 17 без CRM-зависимостей. С новой формой размер составляет около 158 КБ raw / 52 КБ gzip; проверяемый бюджет увеличен с 155 до 160 КБ.
