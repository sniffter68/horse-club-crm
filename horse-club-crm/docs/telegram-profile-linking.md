# Привязка Telegram и роли

Источник требований: задача владельца от 09.11.2026. Бот: `@horseclub68_bot`.

`TelegramLinkService` хранит SHA-256 хеши одноразового токена и шестизначного кода в PostgreSQL. TTL — 15 минут. Новая выдача отзывает предыдущий код; отвязка очищает ID/username и отзывает незавершённую привязку. Выдача, погашение и отвязка выполняются в Serializable-транзакциях. Записывается автор выдачи. Один Telegram может иметь отдельные профили клиента и сотрудника; внутри каждого типа нельзя перехватить чужую привязку. Конфликт требует явной отвязки в CRM, история профилей не переносится автоматически.

Deep-link: `https://t.me/horseclub68_bot?start=link_client_<uuid>_<token>`; для пользователя используется `link_user_…`. Токен — 12 символов base64url, параметр клиента — 61 символ. Ограничение Telegram и разрешённый алфавит: [официальная документация](https://core.telegram.org/bots/features#deep-linking). Коды/токены не записываются в логи или localStorage. Погашение принимает только личные сообщения боту; не более пяти попыток за 15 минут на Telegram ID в текущем процессе. Polling выполняется одной репликой backend.

| API | Доступ |
| --- | --- |
| `POST /api/clients/:id/telegram-link`, `DELETE /api/clients/:id/telegram` | ADMIN/MANAGER, полный доступ к SCHEDULE |
| `POST /api/users/:id/telegram-link`, `DELETE /api/users/:id/telegram` | ADMIN/MANAGER, полный доступ к STAFF_PAYROLL; профиль ADMIN может связывать только ADMIN |
| `GET /api/clients/:id/telegram` | ADMIN/MANAGER/TRAINER с доступом к SCHEDULE |
| `GET /api/users/:id/telegram` | ADMIN/MANAGER с доступом к STAFF_PAYROLL |

Выдача возвращает `{ code, expiresAt, deepLink, role }`. Для пользователя необязательный флаг `role: staff | trainer | admin` проверяется против текущей роли CRM и не назначает права. UUID валидируется сервером и UI. READ_ONLY/HIDDEN запрещают мутации серверным ModuleAccessGuard; UI скрывает соответствующие действия.

Клиент связан с `Client.telegramUserId`, сотрудник — с `User.telegramUserId`; тренер определяется через `User.trainerId`. Старое поле `Trainer.telegramId` не используется для новой авторизации. Username сохраняется отдельно и используется только для отображения. Неактивный персонал и архивные клиенты не получают личные данные через бота.

Клиентское меню открывает существующую TMA, свои предстоящие записи и остатки личных/семейных абонементов. Сотрудник видит свои смены, связанный тренер — свои занятия на сегодня или ближайшие семь дней по Москве. Для изменения статуса проверяются актуальные права и владелец занятия повторно внутри финансовой транзакции. Бот использует LessonsService: завершение, списание посещений, отмена и восстановление посещений сохраняют существующие правила. Отмена требует подтверждения с явным выбором возврата денег; денежный возврат требует полного доступа к кассе. Для смешанных способов оплаты решение по возврату принимается в CRM.

Администраторы получают алерты о новых записях TMA, заявках с лендинга, запросах отмены из TMA и отменах занятий. Клиенты получают подтверждение, перенос, отмену и завершение занятия. `TelegramNotification` — постоянная очередь со стабильным ключом события, попытками доставки и повтором после временных ошибок. TMA/занятия ставят события в очередь внутри бизнес-транзакции. Заявки с сайта сохраняют существующий порядок: заявка фиксируется первой, VK и Telegram ставятся в очередь независимо; повторная отправка восстанавливает пропущенную запись очереди. Перед отправкой проверяются текущая привязка, роль и активность получателя. Доставка имеет семантику at-least-once: при аварии между ответом Telegram и сохранением `sentAt` возможен повтор.

UI: общий `TelegramProfileLink` в контактах клиента, таблице пользователей и шторке персонала. Ant Design Modal показывает код, TTL, ссылку и ошибку с повтором. Статус опрашивается раз в три секунды только при открытом диалоге; закрытие отменяет запросы. Подтверждение бота обновляет карточки без перезагрузки. Отвязка требует отдельного подтверждения; ошибка остаётся в диалоге. После обновления кода фокус переходит к ссылке, после закрытия — к кнопке вызова.

## Развёртывание

Применить миграцию `20261109120000_telegram_link_roles` на сервере через `npx prisma migrate deploy`, сгенерировать Prisma Client и пересобрать backend/frontend. Используются существующие `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBAPP_URL`, необязательный `TELEGRAM_API_ROOT`. До применения миграции новую сборку запускать нельзя. Живой бот и серверная БД локальными mock-проверками не изменяются.

Проверки: `backend/test/telegram-link.test.cjs`, полный backend test, frontend unit-тесты, `frontend/e2e/telegram-link.spec.ts`, регрессия `vk-link.spec.ts`. Статический premium-аудит всего проекта находит прежние нарушения и ложные срабатывания на Ant Design Form.Item/Select и Button с href; корректность ссылки подтверждается браузерным `getByRole('link')`. Это не замена runtime-проверкам.
