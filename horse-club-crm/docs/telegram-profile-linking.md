# Привязка Telegram

Источник требований: задача владельца от 09.11.2026. Бот: `@horseclub68_bot`.

Клиент и сотрудник связываются через ввод username, ссылки `https://t.me/username`, `t.me/username` или числового ID. Сервер удаляет пробелы, префиксы и завершающий слеш, приводит username к нижнему регистру. Числовой ID сохраняется строкой в `telegramUserId`, ник — в `telegramUsername`; противоположное поле очищается. Некорректный ввод возвращает 400, занятый ID/username внутри одного типа профилей — 409.

| API | Доступ |
| --- | --- |
| `PATCH /api/clients/:id/telegram`, `DELETE /api/clients/:id/telegram` | ADMIN/MANAGER, полный доступ к SCHEDULE |
| `PATCH /api/users/:id/telegram`, `DELETE /api/users/:id/telegram` | ADMIN/MANAGER, полный доступ к STAFF_PAYROLL; профиль ADMIN может изменять только ADMIN |
| `GET /api/clients/:id/telegram` | ADMIN/MANAGER/TRAINER с доступом к SCHEDULE |
| `GET /api/users/:id/telegram` | ADMIN/MANAGER с доступом к STAFF_PAYROLL |

PATCH принимает `{ username: string }`, возвращает `{ telegramUserId, telegramUsername }`. DELETE очищает оба поля. UUID проверяется сервером и UI. READ_ONLY/HIDDEN запрещают мутации через ModuleAccessGuard. Изменения выполняются в Serializable-транзакциях с ограниченным повтором конфликтов сериализации.

Глобальный middleware бота получает подтвержденные Telegram ID и username из `ctx.from` до обработки команды или другого апдейта. Такой же сервис вызывается после проверки подписи TMA initData и до upsert клиента, чтобы использовать существующую карточку. По username в нижнем регистре находится профиль с пустым `telegramUserId`, затем записывается числовой ID. Уже связанный профиль не перезаписывается; неоднозначные совпадения, архивные клиенты и неактивные сотрудники пропускаются. Один Telegram может иметь отдельные профили клиента и сотрудника. Роли берутся только из CRM.

Общий `TelegramProfileLink` используется в карточке клиента, таблице пользователей и форме персонала. Как и VK, ввод открывается в `EntryOverlay` справа. Кнопка «Сохранить» отправляет PATCH; ошибка сохраняет введенный текст, загрузка блокирует повторную отправку. Сохраненный username сразу показывает мягкий бейдж, ссылку `https://t.me/username` и «Отвязать», даже до получения ID ботом. Для числового ID показывается бейдж ID. Отвязка требует отдельного подтверждения. Закрытие возвращает фокус кнопке вызова. Кодов, таймеров и опроса статуса больше нет; старые эндпоинты выдачи кода удалены.

Существующие `TelegramLinkToken` и исторические миграции сохраняются для совместимости схемы; новые токены не выдаются и не погашаются. Сохранение и отвязка удаляют старые токены этого профиля.

Персональные меню, проверки владельца и актуальных прав, финансовые транзакции LessonsService и постоянная очередь TelegramNotification сохраняют действующие правила. Перед доставкой уведомления повторно проверяются текущая привязка, роль и активность получателя.

Новая миграция не требуется: оба поля и уникальные индексы ID уже описаны в схеме и миграциях `20261108000000_telegram_mini_app` / `20261109120000_telegram_link_roles`. При развертывании должны быть применены существующие миграции. Используются `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBAPP_URL`, необязательный `TELEGRAM_API_ROOT`; polling запускается одной репликой backend.

Проверки: backend mock/HTTP/dispatch-тесты `telegram-link.test.cjs`, подписанная авторизация TMA в `telegram-bot.test.cjs`, браузерные сценарии `telegram-link.spec.ts` и регрессия `vk-link.spec.ts`.
