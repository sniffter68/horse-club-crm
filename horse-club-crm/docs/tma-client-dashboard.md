# Стартовый экран Telegram Mini App

Корневой `/tma` сохраняет приоритет серверного bootstrap: TRAINER сразу получает
`TrainerScheduleView`, ADMIN — существующий административный режим. CLIENT
переходит в отдельную сборку `/tma/client` с параметрами запуска Telegram.

Клиентская сборка сначала запрашивает `GET /api/tma/dashboard` с подписанным
initData. Пока запрос выполняется, каталог не монтируется. Ошибка показывает
повтор загрузки и не классифицирует посетителя как нового.

Telegram автоматически создает минимальную карточку клиента. Поэтому кабинет
открывается при наличии телефона, email, даты рождения, уровня всадника,
предпочтений, выбранного тренера/лошади, истории записей, личного или семейного
абонемента либо договора постоя. Старый абонемент также сохраняет клиентский
кабинет стартовым экраном. Только пустая автоматически созданная карточка
без истории получает каталог по умолчанию.

`ClientDashboardView` показывает общий `MembershipCard` с остатком и progress,
сроком по Москве и предупреждением об окончании; ближайшую тренировку с тренером
и статусом; кнопку «+ Записаться на занятие». Кнопка открывает
`ClientBookingCatalog` и существующий выбор услуги/времени. Telegram BackButton
возвращает из каталога в кабинет. Повторный вход в кабинет обновляет данные.

API ограничивает все выборки подписанным clientId. Ближайшее занятие выбирается
отдельно от страниц истории, по возрастанию времени, с исключением отмененных,
проведенных и архивированных занятий. Личные и семейные активные абонементы
выбираются существующим `activeTelegramMembership`.

Новые зависимости не добавлены. Контролируемый лимит JS+CSS TMA увеличен
с 150 до 155 КБ для кабинета; сборка остается отдельной от CRM.
Схема Prisma не менялась, генерация клиента и миграция не требуются.

Проверки: backend/test/tma-dashboard.test.cjs, tma/e2e/booking.spec.ts,
frontend/e2e/trainer-tma.spec.ts. Логи текущей проверки: test-results/dashboard-*.

успешно. Backend — 772 passed, 21 skipped (интеграционные окружения),
frontend — 175 passed; браузер — 14 тренерских и 17 клиентских сценариев.
Линтер backend сохраняет три предупреждения в ранее существовавших тестах.
