# Прямая привязка тренера к VK

В `/trainers` при создании или редактировании тренера указывается единственное поле «VK ID»: число, `id123`, ссылка `vk.com/id123` или имя личной страницы. Имена разрешаются общим `VkIdentityService.normalize` через API VK; для этого нужен настроенный токен сообщества. Пустое поле снимает привязку. После сохранения тренер пишет боту `/start` и сразу получает своё меню.

Модель Trainer содержит только `vkId BigInt? @unique` для VK. Полей и команд временных кодов нет. User/Staff не создаются и не требуются. Прямой поиск активного тренера первым запросом возвращает `{ type: 'TRAINER', id, name }`; просмотр расписания и отметка посещения используют только этот id. Привязка User к Trainer сама по себе не открывает тренерские действия бота. Настройки VK сотрудников больше не изменяют VK тренеров и наоборот.

API создания и обновления принимает числовой или строковый vkId; хранит проверенный числовой ID в BigInt. JSON-интерцептор возвращает его строкой для сохранения точности. PATCH `/api/trainers/:id/vk` сохранён как короткий маршрут того же прямого обновления из карточки. Доступ к мутациям: ADMIN/MANAGER с FULL SCHEDULE. READ_ONLY скрывает действия. Уникальность проверяется в serializable-транзакции; чужой клиент/сотрудник/тренер вызывает 409. Существующая учётная запись того же тренера с тем же ID допускается для совместимости, но не используется для идентификации тренера.

Уведомления о создании, переносе и отмене занятий получают получателя напрямую из Trainer.vkId. Смена или очистка ID отзывает неотправленные уведомления для прежнего получателя. trainerId в Lessons/Bookings не меняется. Старые коды тренеров удаляются миграцией, выдача и применение кодов для TRAINER запрещены; существующие клиентские коды сохранены.

Миграция `20261105120000_simplify_trainer_vk_binding` переименовывает прежнюю BigInt-колонку vkUserId и её уникальный индекс, сохраняя значения. Миграция с PIN из промежуточной реализации не применялась. На сервере перед запуском новой версии выполнить `npx prisma migrate deploy`; Prisma Client сгенерирован локально. Обновлять backend и схему следует совместно: прежняя версия ожидает старое имя колонки.

Проверки: `backend/test/trainer-vk-binding.test.cjs`, существующие тесты VK и уведомлений, `frontend/e2e/vk-link.spec.ts` (1280/390px, ошибка/повтор/очистка, клавиатура). PostgreSQL-сценарии требуют доступной тестовой БД.
