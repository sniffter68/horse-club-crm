Сканер, в частности, ошибочно классифицирует Ant Design Form.Item/Select как нативные поля; результаты сравнения сохранены локально в `docs/test-reports/service-refund-ui-audit.json` (генерируемый файл исключён из Git правилами проекта). Новый общий диалог использует существующие Ant Design компоненты и форму noValidate.

Основные backend-сценарии: наличный возврат уменьшает клубный баланс один раз; банковский возврат не затрагивает наличные; удержание не меняет баланс и фиксируется в аудите; сбой после создания расхода откатывает расход, аудит, долги и состояние услуги; сумма ограничена оплатой/неиспользованным остатком; бывшие участники получают возврат списанного посещения; повторная отмена не создаёт повторного расхода.

Для постоя возвращается принятая сумма целиком, поскольку чеки не содержат оплаченного периода для пропорционального расчёта дней. Для живой проверки применения миграции и фактического production-развёртывания требуется успешный запуск GitHub Actions после push.
