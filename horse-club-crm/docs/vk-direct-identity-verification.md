# Проверка прямой привязки VK

Реализованы поля Prisma и миграция с переносом существующих связей, нормализация числовых ID/ссылок/коротких имен, общая проверка уникальности клиентов и сотрудников, защищенный API идентификации, прямое определение роли в webhook, формы и ссылки VK в CRM. Коды и телефон больше не используются для привязки.

Проверки завершены:

Unit-тесты проверяют нормализацию и ошибки VK API, конфликт VK ID между таблицами, повтор сериализации, отзыв ожидающих уведомлений, сохранение/очистку клиента и сотрудника, ответы CLIENT/STAFF/UNKNOWN, сервисный токен и права PATCH. Браузерные сценарии проверяют ввод ссылки без телефона, конфликт 409 с сохранением ввода, снятие привязки, сотрудника/тренера, READ_ONLY, узкий экран 320px, темную тему, Escape и возврат фокуса. Дополнительно проверена регрессия клиентских предпочтений. Темная шторка просмотрена на скриншоте.

Дополнительный статический аудит frontend-design-premium запущен в strict-режиме: 202 эвристических замечания, включая ошибочное распознавание Ant Design `Form.Item` как отдельной формы и Ant Design `Select` как native select. Этот аудит не является прошедшей проверкой; его замечания требуют отдельной проверки всего интерфейса. Проверки проекта и измененного поведения выше прошли.

Живые запросы к VK и применение миграции к PostgreSQL локально не выполнялись. Пропущенные backend-тесты требуют отдельной интеграционной среды. Миграция `20261026120000_vk_direct_identity` применяется серверным этапом `prisma migrate deploy`; генерация клиента предусмотрена Dockerfile. Для внешнего GET `/api/vk/identify` нужно задать отдельный `VK_IDENTIFY_TOKEN` в `.env.production`. Встроенный webhook вызывает тот же сервис напрямую.

Запуск `scripts/deploy-commit.ps1` создает коммит и push в main; завершение серверного деплоя подтверждается отдельно в GitHub Actions.
