# Персональные меню VK-бота: проверка

Реализован `POST /api/vk/webhook`; прежние callback-адреса сохранены. Webhook возвращает строку `VK_CONFIRMATION_CODE`, проверяет `VK_SECRET_KEY` из JSON или заголовков и, если задан, `VK_GROUP_ID`. Сообщения обрабатывает существующий VkBotService через общий сервис идентификации CRM. Персональные данные доступны только в личном диалоге соответствующего пользователя.

Клиентская клавиатура: «🎫 Мой абонемент», «📅 Мои тренировки», «💬 Администратор». Семейные пакеты выбираются через общий `membershipAccessWhere`; показываются общий остаток, семейная связь и окончание срока. Предстоящие записи исключают отмены и архивные занятия.

Тренерская клавиатура: «📋 Расписание на сегодня», «👥 Мои всадники». Выборка ограничена своим trainerId и московскими сутками, включает Lesson и самостоятельные Booking без дублирования. Inline-отметки посещения сохранены только для Lesson, поддерживаемых текущим финансовым журналом.

Гостевая клавиатура: «О клубе», «Услуги и цены», «Как доехать», «Связаться». Цены берутся из публичного каталога CRM. Гость получает пояснение о привязке VK администратором. Тексты не содержат кодов привязки или запроса телефона для идентификации.

Добавлен `VK_GROUP_TOKEN` в backend `.env.example`, production-пример и Compose. Существующие `VK_COMMUNITY_TOKEN`/`VK_BOT_TOKEN` поддерживаются. Полная конфигурация проверяется до запуска приложения. `messages.send` использует VK API 5.199, стабильный random_id и клавиатуры vk-io; длинные ответы делятся на безопасные части.

Покрыты текстовые команды и payload, точный состав клавиатур, новый и старые токены, неполная конфигурация, confirmation, секрет из заголовков/тела, неверная группа, семейный пакет, будущие записи, расписание/всадники Москвы и разделение длинных сообщений. Регрессионные тесты проверяют привязку клиента и сотрудника, конфликт уникальности, READ_ONLY, мобильный экран и клавиатурное закрытие шторки.

Схема БД не менялась: новая миграция и генерация Prisma Client для этой задачи не требуются. Реальные сообщения в VK не отправлялись; транспорт VK и база данных проверены через моки, HTTP-обработчики — через Nest/supertest. 17 backend-тестов требуют отдельной интеграционной среды. Webhook подтверждает событие до окончания обработки; после подтверждения ошибки обработки фиксируются в журнале.

Для нового подключения указать `https://crm.horseclub68.ru/api/vk/webhook` в Callback API сообщества, настроить token/confirmation/secret и включить `message_new` (а для отметок посещения — `message_event`). Старый настроенный callback остается рабочим. Результат серверного автодеплоя подтверждается отдельно в GitHub Actions.
