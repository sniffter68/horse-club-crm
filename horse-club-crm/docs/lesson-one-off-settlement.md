# Разовая оплата отложенного занятия

Источник: задача владельца от 11.11.2026.

В текущей модели нет отдельного флага будущего абонемента: это неоплаченное занятие без привязанного абонемента. Связь кассового `Payment` с занятием проходит через `bookingId → Booking.lessonId`. Отдельной сущности кассы/счёта нет; кассовая операция сохраняет кассира и открытую смену.

В карточке неоплаченного занятия доступны режимы «В счет будущего абонемента / оплатить позже», «Разовое занятие», «Списание с активного абонемента». Отложенный режим сохраняет текущее состояние. Разовый открывает существующую кассовую форму с выбранными клиентом и занятием. При нулевой стоимости подставляется цена услуги, сумму можно изменить вручную. Используются существующие способы оплаты: CASH, CARD_TERMINAL, SBP, TRANSFER.

`POST /api/payments/cash-desk` принимает дополнительное необязательное поле `lessonCost` (положительная сумма с точностью до копеек). Оно разрешено только для занятия расписания с одним плательщиком, без абонемента и принятых оплат. Переданная сумма платежа должна совпадать с новой стоимостью. Для изменения необходим FULL SCHEDULE; приём денег защищён существующим FULL CASHBOX. ADMIN сохраняет полный доступ.

Одна Serializable-транзакция сохраняет CashAuditLog с прежней/новой стоимостью, автором и временем, обновляет Booking.costAmount, создаёт Payment и LedgerTransaction, аннулирует ожидающие начисления через CANCELLED и пересчитывает Lesson.cost/paymentStatus/finalPaymentAmount. Статус проведения занятия остаётся прежним. requestId защищает от повторного поступления, включая повтор после потери ответа.

Миграция `20261111120000_lesson_one_off_settlement` добавляет корректировку признанной выручки проведённого занятия через неизменяемую ONE_OFF_PRICE_ADJUSTMENT. Исходная проводка остаётся в журнале. Отмена добавляет ONE_OFF_PRICE_ADJUSTMENT_REVERSAL; закрытый финансовый период блокирует корректировку и откатывает оплату целиком. Модель Prisma не меняется.

Быстрая запись больше не блокирует тренера, переданного как начальный ресурс. Общая форма и useClientPreferences сохраняют ручной выбор; CreateLessonDto требует UUID, createLesson использует dto.trainerId.

## Проверка в приложении

1. Выбрать клиента с тренером по умолчанию, выбрать другого тренера и создать занятие. Открыть карточку и проверить назначенного тренера.
2. Открыть проведённое неоплаченное занятие без абонемента. Выбрать «Разовое занятие», изменить сумму, выбрать наличные/терминал/перевод и провести платёж.
3. Убедиться, что занятие сохранило ID и статус проведения, получило PAID и новую стоимость, а касса содержит одно поступление с нужными клиентом и занятием.
4. Обновить страницу; повторить запрос с прежним requestId — второго поступления быть не должно.
5. Для занятия с исходной нулевой ценой проверить подстановку цены услуги. При отмене проверить сторнирование всей признанной выручки без удаления исходных проводок.

## Команды проверки

В backend и frontend: `npm run typecheck`, `npm run lint`, `npm run build`, `npm test`.
На Windows с заблокированным npm.ps1 использовать `npm.cmd`.

Браузер: `npm --prefix frontend run test:e2e:mock -- e2e/lesson-payments.spec.ts` при работающем Vite на localhost:5173.
Изолированная PostgreSQL-проверка: `npm --prefix backend run test:memberships:postgres`.

Перед выпуском применить миграции на сервере из backend: `npx prisma migrate deploy`. Prisma Client сгенерирован командой `npx prisma generate --schema backend/prisma/schema.prisma` из корня.
