# Стоимость и оплата разовых занятий

`POST /lessons` принимает `cost`, `prepaymentAmount`, `prepaymentMethod` (`CASH` / `CARD`) для одного записываемого клиента без абонемента. Без `cost` фиксируется текущая цена услуги. Предоплата не превышает стоимость; суммы имеют точность до копеек. Для группового запроса цена берётся из услуги для каждого участника без абонемента. Индивидуального участника с согласованной ценой и предоплатой можно добавить в существующий групповой слот.

`POST /lessons/:id/complete` и `PATCH /lessons/:id/status` со статусом `COMPLETED` принимают `payRemaining`, `paymentMethod`, `customAmount`. Без явного выбора оплаты занятие завершается с долгом. Переданный способ оплаты без `payRemaining` означает приём остатка; явный `payRemaining: false` отключает приём денег. Частичная `customAmount` сохраняет `PARTIALLY_PAID`, сумма выше остатка отклоняется. Повторное завершение возвращает сохранённый результат. Оставшийся после завершения долг принимается через обычную кассу.

Стоимость и суммы хранятся в `Lesson`, индивидуальные суммы — в `Booking`, где стоимость уже представлена `costAmount`. Это позволяет правильно рассчитывать остатки участников смешанного группового занятия. Новые разовые записи сохраняют выбор оплаты деньгами; система не подменяет его автоматически найденным абонементом. Для исторических записей `cost = NULL` сохраняет прежнее разрешение абонемента при завершении. Связанный абонемент списывается существующим MembershipLedgerService.

Касса в проекте представлена `Payment` и `LedgerTransaction`. Предоплата и доплата создают отдельные `PAID` платежи и связанные `purchase` проводки. Категории `LESSON_PREPAYMENT` и `LESSON_PAYMENT` записываются в существующее поле `Payment.serviceType`. Клиент и занятие связаны через `bookingId → Booking.lessonId`; автор и время — через `cashierId`, `paidAt`, `createdAt`. Открытая смена привязывается при наличии. Непогашенное начисление `PENDING` уменьшается до остатка и отменяется после полной оплаты; исходные кассовые приходы не переписываются.

Все изменения занятия, участников, платежей и проводок выполняются в общей транзакции Serializable с существующим повтором при конфликте сериализации. Если касса выключена, суммы сохраняются без кассовых проводок. Если касса включена, нужен FULL CASHBOX; ADMIN имеет полный доступ. Для создания и завершения также требуется FULL SCHEDULE. Отмена занятия не создаёт автоматический денежный возврат.

Формы календаря и дашборда используют общий финансовый блок. При завершении выбор долга установлен первоначально, чтобы пользователь явно подтвердил получение денег. Карточки показывают мягкие бейджи оплаты. После ошибки выбор сохраняется; повторная отправка блокируется на время запроса. Суммы отображаются в рублях, даты — по Москве.

## Миграция и проверка

Миграция `20261020120000_lesson_payments` добавляет поля и enum, ограничения неотрицательных сумм и запрет превышения стоимости. Старые кассовые записи сохраняются. На сервере после обновления кода выполнить `npx prisma migrate deploy` и `npx prisma generate` перед запуском обновлённого backend. Локально миграция к базе не применялась.

Проверки: `backend/test/lesson-payments.test.cjs`, дополнительный сценарий погашения долга в `backend/test/cash-desk.test.cjs`; Playwright `lesson-payments.spec.ts` проверяет UI с API-моками на 1440/390 px, два прихода в журнале кассы, отказ сервера и полную предоплату. `dashboard.spec.ts` проверяет шторку, предоплату, READ_ONLY кассы и подтверждение завершения. Эти браузерные тесты не заменяют проверку миграции на PostgreSQL.
