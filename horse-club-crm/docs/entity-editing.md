# Закрепленное меню и редактирование карточек

`AppLayout` задает высоту экрана, `main.crm-main` отвечает за вертикальную
прокрутку содержимого. Desktop Sidebar имеет собственную прокрутку меню;
на экранах уже 992 px сохраняется мобильная навигационная шторка.

В карточках клиента, лошади и тренера `CatalogEditAction` открывает общую
шторку с существующей формой каталога. `CatalogDrawerForm` загружает запись,
проверяет UUID и отправляет PATCH. `StableEntryModal` блокирует повторные
отправки, сохраняет ввод при ошибке, предупреждает о потере изменений,
инвалидирует все запросы соответствующего ресурса Refine, включая карточку,
и показывает уведомление об успехе. Во время загрузки фото сохранение
заблокировано. Отдельная страница редактирования остается доступной.

Редактирование персонала использует ту же шторку и существующий `/staff/:id`.
Кнопки скрыты при READ_ONLY, ставки тренеров требуют FULL STAFF_PAYROLL.
Изменения лошадей требуют FULL STABLES, изменения тренеров — FULL SCHEDULE.
Сервер проверяет оба требования при изменении ставки тренера; чтение общих
каталогов для расписания сохраняет прежнюю политику.
Телефоны показываются с маской и отправляются без форматирующих символов.
Даты рождения хранятся как календарная строка YYYY-MM-DD без сдвига часового
пояса. Цвет тренера обозначает рамку события календаря, сохраняя цвета статусов.

## Развертывание

Перед запуском обновленного backend применить миграцию
`20261021180000_entity_edit_fields` командой `npx prisma migrate deploy` на
сервере и сгенерировать Prisma Client. Миграция добавляет только nullable-поля:
Client.birthDate, Horse.coat, Trainer.scheduleColor, StaffProfile.phone,
StaffProfile.scheduleColor. Тип и владелец лошади используют существующие поля.

## Проверки

- `frontend/e2e/entity-edit.spec.ts`: ошибки и повторное сохранение клиента,
  лошади и тренера на 1440/390 px; сотрудник; READ_ONLY; неподвижность Sidebar
  после прокрутки на 1024/1440/1920 px.
- `backend/test/entity-edit.test.cjs`: валидация дат, UUID и цветов, сохранение
  новых полей через сервисы с mock Prisma, синхронизация статуса и нагрузки.
- `frontend/src/components/formatPhone.test.ts`: маска и формат API телефона.
- Реальная PostgreSQL этими mock-сценариями не проверяется. Проверка записи
  новых полей в PostgreSQL необходима после применения миграции на сервере.
- Общий статический premium-аудит обнаруживает существующие нарушения и
  ложные срабатывания: Ant Design `Form.Item` определяется как отдельная
  форма, а `Select` — как нативный select. Результат не является подтверждением
  качества работающего интерфейса; runtime-проверки выполняются отдельно.

Итог локального прогона 21.10.2026: typecheck, Oxlint и build обоих проектов
успешны; frontend — 139 unit-тестов, backend — 484 теста и 17 пропусков,
Playwright `entity-edit.spec.ts` + `module-access.spec.ts` — 22/22.
Oxlint backend сообщает три предупреждения в существующих тестах, ошибок нет.
Дополнительный прогон `s3-01.spec.ts` выявил один сбой старого сценария
бронирования: `getByLabel('Клиент')` находит два элемента Ant Design Select.
Изменения этого старого теста не включены. Статический premium-аудит завершился
с кодом 1 и 197 замечаниями по проекту, включая указанные ложные срабатывания.
