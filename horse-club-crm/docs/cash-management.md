# Сброс кассы и инкассация

Решение владельца от 2026-10-21. В текущем enum Role владелец использует ADMIN;
OWNER отсутствует. Оба новых маршрута требуют действующую JWT/cookie-сессию,
ADMIN и доступ к модулю CASHBOX. Автор берётся из сессии.

## API и сохранность данных

- `POST /api/cash/reset`: `{ confirmation: "RESET_CASH", requestId?: UUID }`.
  Возвращает `{ success: true, message: "Касса и история операций успешно обнулены", currentBalance: 0 }`.
  Архивирует Payment, Expense и CashShift через archivedAt, закрывает открытые смены.
  Активные журналы и расчёты кассы исключают архив; наличный и безналичный остатки становятся нулевыми.
  Сохраняет связи LedgerTransaction, Booking, Membership и PayrollCalculation, статусы оплат,
  остатки абонементов и сведения о выплаченных зарплатах. Самих клиентов и занятия не удаляет.
  Архивные платежи/расходы нельзя редактировать или удалять через старые операции кассы.
  Интерфейса восстановления архива нет.
- `POST /api/cash/withdraw`: `{ amount: number, requestId: UUID }`.
  Положительная сумма до 9999999999.99, точность две цифры после запятой.
  Проверяет накопительный активный наличный остаток, создаёт Expense с CASH, OTHER,
  isEncashment=true и описанием «Передача выручки владельцу».
  Инкассация остаётся в истории расходов, её отмена через обычное удаление расхода запрещена.
  Размен смены не входит в доступный остаток согласно существующему контракту `docs/expenses.md`.
  Закрытие смены остаётся отдельным штатным действием `/payments/shifts/:id/close`.

Операции выполняются в Serializable-транзакции с повторами конфликтов сериализации.
Короткая EXCLUSIVE-блокировка Payment, Expense и CashShift упорядочивает сброс/выемки
с существующими писателями, включая старые API. Читающие SELECT не блокируются.
CashAuditLog сохраняет автора, его имя (либо email), дату, действие и подробности.
Сбой аудита откатывает всю операцию. Аудит не очищается при следующих сбросах.

Повтор с тем же requestId возвращает исходный результат и не создаёт вторую операцию.
Для сброса API допускает отсутствие requestId, но для безопасного сетевого повтора его
следует всегда передавать: интерфейс так и делает. Повтор исходного сброса после новых
платежей не архивирует эти новые платежи; currentBalance: 0 подтверждает результат исходного сброса.

## Интерфейс

ADMIN видит действия при FULL CASHBOX. Диалог сброса требует точное слово «СБРОСИТЬ»;
фокус начинается на безопасном действии. Инкассация использует общий EntryOverlay drawer.
Успех обновляет кассовые данные через существующее событие cash-desk-paid и инвалидирует
Refine payments. Сброс переводит журнал на сегодня/первую страницу, убирает текущую смену.
Ошибки остаются в форме. При неопределённом результате сумма заблокирована, повтор использует
тот же ключ и payload. После явного отказа 4xx сумма снова доступна для исправления.

## Выпуск и проверки

Миграция: `backend/prisma/migrations/20261021090000_cash_management/migration.sql`.
На сервере требуется `npx prisma migrate deploy`, затем `npx prisma generate` и обычная сборка.
Миграция добавляет поля/таблицу, сама данные не обнуляет. Сброс запускается владельцем из CRM.

Тесты: `backend/test/cash-management.test.cjs`, `frontend/e2e/cash-desk.spec.ts`.
Backend `npm run lint` использует установленный в frontend Oxlint: перед проверкой нужны
зависимости обоих проектов. PostgreSQL-проверки общего npm test требуют отдельной тестовой БД.
