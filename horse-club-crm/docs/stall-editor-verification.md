# Редактирование параметров денников — 21.11.2026

## Диагностика и изменения

- Источник данных — Prisma `Stall.name` и `Stall.number`, типы `STALL`, `PONY_PEN`, `SERVICE`. Полей `title`, `DEN`, `x/y/width/height` и отдельного PUT `/stable/stalls` в этом потоке нет. `/stable` отображает карту, `/stalls` — список. Геометрия хранится в `buildingId`, `row`, `col`, `rowSpan`, `colSpan`.
- Имеющийся PATCH `/stalls/:id` сохранял оба поля в транзакции. Проверено повторным GET и чтением PostgreSQL; универсальный дефект записи этого PATCH не воспроизведён. Устранены неоднозначность карточки (она теперь показывает и номер, и название), отсутствие поиска по номеру и ограничение формы списка размерами 3×2: оно блокировало сохранение имени помещения с большими допустимыми размерами.
- В конструкторе кнопки помещений были отключены; PATCH `/stalls/layout` принимал только геометрию и не записывал аудит. Теперь кнопка любого помещения, включая неразмещённое, открывает существующую правую шторку с параметрами.
- «Применить к схеме» обновляет черновик и плашку без запроса. Общее сохранение отправляет весь черновик. «Сохранить изменения» в шторке сохраняет всю текущую раскладку, оставляя конструктор включённым. Неизменённые названия/номера не отправляются повторно при перемещении других помещений.
- API layout принимает также name/number/type. Проверки границ и пересечений выполняются для итогового состояния. Параметры, номер заселённой лошади и CashAuditLog записываются в одной Serializable-транзакции. Сбой аудита откатывает запись. Занятое помещение нельзя преобразовать в SERVICE. Аудит содержит актёра, время (стандартное поле CashAuditLog), значения до/после, включая тип и геометрию.
- Ответ сервера немедленно обновляет состояние карты; инвалидируются ресурсы Refine stalls/horses. SERVICE не получает номер, префикс № и прочерк размещения. Ошибка оставляет форму/черновик для повтора; READ_ONLY не показывает конструктор.

- Frontend: `npm.cmd --prefix frontend run typecheck`, `run lint`, `run build`, `test`. 23 файла / 191 тест passed; ошибок линтера и типов нет.
- PostgreSQL: `STALL_TEST_PORT=5432`, `STALL_TEST_SCHEMA_ONLY=1`, `STALL_TEST_FOCUSED=1`, `npm.cmd --prefix backend run test:stalls:postgres`: 23 passed, 0 skipped/failed. Runner создаёт отдельную временную схему, применяет миграции только в ней и удаляет её в finally. Проверены реальные значения name/number/type/геометрии после повторного чтения, номер лошади, аудит и откат.
- Браузер: `npm.cmd --prefix frontend run test:e2e:mock -- stall-map.spec.ts`: 22 passed. Дополнительный прогон `--grep 'list edits'`: 1 passed после расширения сценария размерами 4×3. Сценарии переименования карты и списка включают reload; карточка списка показывает сохранённый номер. Конструктор проверяется для STALL и SERVICE, общего и немедленного сохранения, переноса в корпус, размеров, ошибки/повтора и мобильного экрана. Скриншоты создаются в `frontend/test-results/constructor-room-*.png`.

## Ограничения общей проверки

Запрошенные скиллы `nestjs-crm-architect`, `react-tailwind-ui-polish`, `playwright-e2e-guardian` не найдены ни в проекте, ни в локальных каталогах скиллов. Применены регламент AGENTS.md, существующие архитектурные/тестовые паттерны и доступные frontend-design/frontend-design-premium.

Настроенный PostgreSQL на 5433 недоступен; использован локальный 5432 с временной схемой. Полный DB-runner дополнительно включает посторонний `concurrency-hardening.test.cjs`: три его вложенные проверки записи занятий падают (несовпадение ожидаемых HTTP-статусов и отсутствующие созданные занятия); сценарии денников при этом проходят. Для воспроизводимой профильной проверки добавлен необязательный `STALL_TEST_FOCUSED=1`; обычный запуск не изменён.

Общий strict-аудитор frontend-design сообщает 242 находки по всему репозиторию, включая ложные распознавания `Form.Item` как самостоятельного `<Form>` без noValidate. Фактической формой шторки владеет `StableEntryModal`, где noValidate уже задан. Результат аудитора не считается успешным и не заменяет проверки проекта/браузера. Визуальные токены не изменялись.

Схема Prisma не менялась. Генерация клиента и новая миграция для внедрения не нужны. Изменения не развёрнуты на сервере.
