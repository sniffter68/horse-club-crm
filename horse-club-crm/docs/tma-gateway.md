# Единый вход Telegram Mini App

`POST /api/tma/bootstrap` принимает только `{ initData }` (DTO, максимум 16384 символа). Существующий валидатор проверяет HMAC, уникальность полей, Telegram user и давность подписи (1 час). Сначала используется `User.telegramUserId`, затем устаревшая `Trainer.telegramId` только у User без собственной Telegram-привязки. Учётная запись сотрудника и активный тренер обязательны для тренерской сессии. ADMIN может работать без Trainer. Остальные посетители получают CLIENT с token=null; отключённые сотрудники получают 403.

Ответ персонала: role ADMIN/TRAINER, token, trainerId (nullable у ADMIN), user { id, name }, accessLevel FULL/READ_ONLY. Токен имеет audience trainer-tma, срок 1 час, версию отзыва; CRM JWT его не принимает. Каждая операция заново проверяет связь и права, мутации дополнительно проверяются внутри доменной транзакции. `GET /api/tma/admin/schedule` доступен только ADMIN, личный `/schedule` требует Trainer. Границы дня — Europe/Moscow. Имена и причины отмены отображаются в существующих карточках, формы изменений сохраняют прежние правила и аудит.

`frontend/src/tma/TmaRootGateway.tsx` выбран до импорта CRM. Корень `/tma` открывает персоналу TrainerScheduleView/AdminTmaView. Клиент получает навигацию на `/tma/client` с сохранением query/hash запуска Telegram: это отдельная существующая React 17 сборка, в то время как персонал использует React 19. Перенаправление сохраняет раздельные runtime и клиентский сценарий. `/tma/trainer` проверяет роль; клиент там получает сообщение о привязке. `/tma/client` всегда открывает клиентскую сборку и её собственную проверку initData. Caddy направляет только корень и trainer на frontend index; остальные TMA-пути — на клиентскую сборку.

Бот устанавливает одну общую Menu Button на /tma при запуске polling, ссылки персонала также идут на /tma. Если установка Telegram API не удалась, предупреждение предлагает перезапуск или настройку BotFather; сам бот продолжает работу.

Отмена занятия формирует текст в `telegram-cancellation.ts`: московские дата/начало/конец, всадник, лошадь и причина для каждого участника. UUID остаются только во внутренних ключах дедупликации. Формат применяется к уведомлениям администратора и клиента.

Схема Prisma не меняется; миграция не нужна. Для выкладки собрать backend, frontend и tma, перезапустить backend и перезагрузить Caddy. Локальная работа не публикует изменения на сервер и не обращается к реальному боту.

## Проверки реализации

- Backend: typecheck, lint и build прошли; npm test — 771 passed, 21 skipped, 0 failed. Пропуски требуют серверной PostgreSQL. Три прежних предупреждения lint в тестах других модулей.
- Frontend: typecheck, lint, build прошли; Vitest — 175 passed; Playwright TMA — 14 passed (Edge, мобильная ширина, темы, роли, READ_ONLY, клавиатура, ошибки, отзыв сессии).
- Клиентская TMA: typecheck, lint, unit и build прошли; 15 браузерных сценариев прошли на прямом /tma/client; JS+CSS 149979 байт без gzip. Сборка сохраняется в frontend/dist/tma после основной frontend-сборки.
- Статический premium-аудит всего репозитория: 215 существующих замечаний вне TMA-файлов. Отчёт test-results/gateway-premium-audit.json. Не является зелёной проверкой всего UI.
- Caddy не установлен локально; проверка его конфигурации и реальный Telegram iOS/Android остаются частью выкладки.
