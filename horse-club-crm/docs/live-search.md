# Живой поиск CRM

Источник: задача владельца от 06.11.2026.

- `LiveSearch` — общий контролируемый компонент Ant Design AutoComplete/Input, совместимый с Form.Item. Поиск применяется через существующий submit формы и прежний фильтр `q` Refine; сортировка, пагинация, тип клиента и архив сохраняют своих владельцев. Смена поискового запроса возвращает Refine на первую страницу.
- Ввод от одного символа, debounce 300 мс; очистка и Enter без задержки, IME не отправляет промежуточный текст. Таймер отменяется при смене значения и размонтировании. Данные разных запросов изолированы ключами кэша Refine; журнал и поиск клиента отменяют HTTP-запросы через AbortController.
- Подсказки каталогов берутся из текущей серверной страницы результата, до восьми строк. Это не отдельный поиск по уже загруженной странице: сервер фильтрует весь каталог. Во время debounce/загрузки старые предложения скрыты. В журнале предложения отбираются из загруженных справочников. Выбор клиента, лошади или тренера открывает существующую карточку с проверкой UUID; прочие списки применяют выбранный текст к фильтру.
- `SearchHighlight` выделяет буквальное совпадение без HTML-вставок и регулярных выражений из пользовательского ввода. Телефон сопоставляется по цифрам с учетом маски и российских префиксов 7/8.
- Сервер клиентов ищет имя, фамилию, отображаемое имя, телефон и email. Сервер тренеров — ФИО и телефон. Сервер лошадей — кличку, породу, ФИО владельца. Телефонный поиск использует параметризованный SQL только для получения совпадающих ID; основной Prisma-фильтр сохраняет архив и прочие ограничения.
- Выбор клиента при записи сохраняет создание постоянного/разового клиента, отмену запросов, ошибки и повторы. Выбор лошади переиспользует Ant Design Select, поддерживает подсветку и сохраняет disabled-опции, проверки нагрузки и веса.
- При ошибке доступны прежние Alert и повторный ввод. Во время поиска поле остается доступным. READ_ONLY не добавляет разрешений на мутации.

Схема БД не меняется, миграция и генерация Prisma Client не нужны.

Проверки: `searchText.test.ts`, `backend/test/live-search.test.cjs`, `frontend/e2e/live-search.spec.ts`, существующие сценарии записи и клиентских форм. Проверка UI использует штатный JSX-адаптер проекта `scripts/audit-ui.py`: исходный HTML-парсер навыка ошибочно распознает Ant Select и Form.Item как HTML-теги.
