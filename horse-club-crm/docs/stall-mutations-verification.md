# Редактирование и удаление денников

## Диагностика

- `UpdateStallDto` уже наследовал поля `name` и `number`; Refine simple-rest использует PATCH. Несоответствие HTTP-метода не обнаружено.
- Шторка карты `/stable` редактировала только статус и заметки. Полей названия/номера и действия удаления не было.
- Обновление всегда проверяло геометрию корпуса, даже при изменении только названия. Некорректная старая раскладка блокировала такую операцию. Теперь проверка выполняется при фактическом изменении расположения.
- В форме списка `buildingId: null` у денника без корпуса отклонялся UUID-валидацией. Теперь это значение, как и пустая строка, означает отсутствие изменения корпуса.
- Удаление было прямым `stall.delete`, без проверки занятости и аудита. В актуальной схеме и миграциях связь BoardingContract уже имеет ON DELETE SET NULL; StallTransferLog хранит независимые UUID без FK. Ошибка FK на завершённой истории из текущих миграций не следует. Фактическая схема рабочей БД в этой сессии не проверена.

## Исправления

- На карте название и номер редактируются в общей `StableEntryModal` со шторкой; список использует существующий `CatalogEditAction` / `CatalogDrawerForm`. В списке отображается отдельная колонка номера.
- Переименование сохраняет нормализованные значения и синхронизирует `Horse.stallNumber` для размещённой лошади.
- Общий `StallDeleteAction` для карты и списка проверяет UUID, запрашивает подтверждение, блокирует повторный запрос, показывает русскую ошибку и обновляет данные после удаления. READ_ONLY не получает действий редактирования и удаления.
- Удаление проверяет horseId, OCCUPIED и ACTIVE/SUSPENDED-договоры. Занятый денник возвращает 400 с предложением освободить его или перевести лошадь.
- Для свободного денника ссылки договоров обнуляются перед удалением в serializable-транзакции. Сами договоры, финансовые записи и журнал перемещений сохраняются.
- Обновление и удаление записывают STALL_UPDATED / STALL_DELETED в существующий общий журнал `CashAuditLog` (именно эта модель используется проектом также для нефинансовых событий). Сохраняются автор, время, UUID денника и названия/номера. Ошибка аудита откатывает всю операцию.

Изменений Prisma schema нет. Новая миграция и генерация Prisma Client не требуются. Применение миграций к рабочей БД не выполнялось.
