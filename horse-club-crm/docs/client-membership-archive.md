# Архив клиентов и абонементов

Источник бизнес-правил: задача владельца от 21.10.2026 о безопасном удалении клиентов и абонементов.

## Хранение и API

`Client.deletedAt` и `Membership.deletedAt` — nullable timestamptz с индексами. Маркер абонемента выбран вместо нового enum: существующий `Membership_sync_balances` пересчитывает status при изменении баланса. Возврат за прошлое занятие не снимает архивный маркер.

- GET `/api/clients` и `/api/memberships`: архив исключён по умолчанию; `includeArchived=true` включает его, `archivedOnly=true` возвращает только архив. Поиск и пагинация применяются к выбранному набору. Boolean query валидируется явно.
- DELETE `/api/clients/:id`: при отсутствии всех связей и нулевом балансе удаляет запись; иначе выставляет `deletedAt`. Проверяются bookings, memberships, payments, transactions, boardingContracts, boardingDailyLogs, ownedHorses и leadRequests.
- POST `/api/clients/:id/restore`: очищает только маркер клиента. Его абонементы и история не изменяются.
- DELETE `/api/memberships/:id` (также `/api/client-memberships/:id`): удаляет только неиспользованную запись без связей и кассового проведения. При наличии bookings/payments/transactions/operations, изменении баланса или `cashboxPosted` архивирует. Начальный CREDIT и его проекция — тоже сохраняемая история. Повторное удаление архивной записи не переводит её в hard delete.
- Ответ удаления: `{ id, softDeleted, message }`. Архивация не оформляет денежный возврат автоматически; сообщение направляет сотрудника в кассу.

Проверка истории и запись выполняются одной Serializable-транзакцией с повтором полного решения при serialization/deadlock. Архивация абонемента использует тот же advisory lock, что журнал списаний. Финансовые записи не удаляются и не отвязываются. Отмена старого занятия по-прежнему может вернуть ранее списанные единицы, не восстанавливая абонемент.

Клиентский и абонементный контроллеры защищены модулем SCHEDULE; мутации требуют FULL и роли ADMIN/MANAGER. UI использует тот же владелец прав. Разрешение кассовой оплаты дополнительно проверяется существующей политикой CASHBOX. Архивные абонементы исключены из выбора в кассе, автоназначения и новых списаний в обоих журналах. Новые записи и продажи для архивного клиента требуют его восстановления.

## Интерфейс

Канонический владелец подтверждения — `clients/ArchiveAction.tsx`: Ant Modal, начальный фокус на отмене, загрузка актуальной карточки и полных `_count`, блокировка повторного запроса, сохраняемая ошибка и повтор. Список клиентов предлагает «Все / Только активные / Архив», серый бейдж и восстановление. Фильтр сохраняется средствами Refine в URL; после удаления страница корректируется по total. Карточка сохраняет архивные абонементы и финансовую историю.

## Развёртывание и проверки

Перед запуском обновлённого API применить на сервере `npx prisma migrate deploy`: миграция `20261021180000_client_membership_archive`. Prisma Client генерируется через `npx prisma generate`. Локальную/рабочую базу при разработке не изменяли.

Покрытие: `backend/test/archive.test.cjs`; браузерные сценарии `frontend/e2e/client-archive.spec.ts` и регрессия `clients-memberships.spec.ts`. Интеграционные проверки настоящего PostgreSQL требуют тестовой базы.
