# Удаление занятия

`DELETE /api/lessons/:id` требует ADMIN или MANAGER и FULL доступа к SCHEDULE. Владелец использует ADMIN; отдельная роль OWNER не вводится по решению пользователя. UUID проверяется ParseUUIDPipe. Ответ: `{ success: true, message: "Занятие успешно удалено" }`. Отсутствующее или повторно удалённое занятие возвращает 404.

В реальной схеме отсутствуют CashTransaction и ClientMembership.usedLessons. Касса представлена Payment и LedgerTransaction; занятие связано с ними через Booking. Баланс посещений хранится в Membership.remainedLessons, а списания — в MembershipOp.

Удаление выполняется в одной Serializable-транзакции с существующим повтором при конфликте сериализации:

1. Журнал DEBIT/REFUND определяет фактически списанные и ещё не возвращённые посещения. MembershipLedgerService возвращает по одному посещению на каждый такой абонемент. Повторяющиеся участники с одним абонементом не умножают возврат. Запланированное посещение без DEBIT не увеличивает баланс. Уже возвращённое при отмене посещение повторно не возвращается.
2. Операции абонемента сохраняются, lessonId обнуляется. Причина сохраняет первоначальный текст и фиксирует UUID удалённого занятия, пользователя и время удаления.
3. Только начисления PENDING становятся CANCELLED. Платежи PAID, их суммы, авторы, даты и проводки LedgerTransaction остаются прежними; автоматический денежный возврат не производится.
4. Booking сохраняется как служебная запись: lessonId = NULL, legacyLessonBinding = true, status = cancelled_club. cancellationReason фиксирует занятие, пользователя и время. Сохраняются ссылки платежей, проводок и история замены лошадей. API списка самостоятельных бронирований исключает эти записи; статус отмены освобождает ресурсы.
5. Lesson удаляется физически. Любая ошибка откатывает все изменения.

## Интерфейс

Общий DeleteLessonAction используется в карточках расписания и журнала занятий. Ant Design Button/Modal/Alert/App message сохраняют текущую тему. Иконка DeleteOutlined взята из используемой проектом библиотеки и скрыта от скринридера как декоративная.

Диалог показывает дату/время по Москве, клиентов, предупреждения о привязанном абонементе и сумме фактических PAID платежей. Начальный фокус — «Отмена». Во время удаления повторный запрос, закрытие диалога и действия карточки блокируются. Ошибка остаётся в диалоге для повторной попытки.

После успеха карточка закрывается, показывается «Занятие удалено из расписания». Refine инвалидирует schedule/lessons/kpi/dashboard/bookings/clients/memberships. Событие lesson-deleted обновляет расписание и сводку дашборда, использующие прямые HTTP-запросы. Журнал перезагружает текущие фильтры и корректирует последнюю страницу после удаления. Для TRAINER, STABLE_WORKER и READ_ONLY кнопка скрыта; сервер независимо проверяет доступ.

## Развёртывание

Перед запуском нового backend применить миграцию `20261021120000_lesson_deletion`: `npx prisma migrate deploy` на сервере. Она меняет Booking.lesson на ON DELETE SET NULL и разрешает отвязанные отменённые служебные записи в Booking_triad_check. MembershipOp.lesson уже использовал SET NULL в БД; теперь поведение явно записано и в schema.prisma. Prisma Client сгенерирован локально. Миграция локально не применялась.
