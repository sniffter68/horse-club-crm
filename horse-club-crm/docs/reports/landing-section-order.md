# Последовательность блоков лендинга

Изменена фактическая точка входа `landing/src/App.tsx`: Hero → О клубе → Услуги → Лошади → Тренеры → Подготовка → Отзывы → FAQ → Запись/контакты → Footer → ScrollToTop. Сертификаты сохранены внутри раздела услуг. Каталоги используют общий компонент карточек и модальных подробностей, но отображаются двумя самостоятельными секциями.

Якоря меню и футера согласованы с секциями. Добавлены #coaches, #preparation, #reviews и #booking; старые #horses-trainers, #first-lesson и #booking-form сохранены. Глобальный smooth scroll учитывает prefers-reduced-motion. Блок отзывов открывает ранее предоставленный источник ВКонтакте, без вымышленных цитат или рейтингов.

## Проверки

- `npm run typecheck`, `npm run lint`, `npm run build` — успешно в landing, frontend и backend. Линтер backend оставляет три существующих предупреждения в тестах, без ошибок.
- `npm test` в frontend: 165 passed.
- `npm test` в backend: 661 passed, 20 skipped.
- `LANDING_TEST_EXTERNAL_SERVER=1 CI=1 npm test -- --reporter=line` в landing: 71 passed, 1 skipped (live API/БД). Использован production preview, поднятый тестовым сервером. Отдельный запуск потребовался из-за зависшего завершения управляемого Playwright сервера на Windows.
- Проверены карусели, форма и ошибки API, клавиатура, доступность, reduced motion, адаптивные размеры 320–1920 px. Новый сценарий проверяет строгий порядок блоков и переходы по якорям на 375/1440 px; скриншоты сохраняются в landing/test-results.
- `npm run audit:ui` из корня: оба проектных аудита прошли без замечаний. Стандартный audit_project.py навыка также проходит для landing; его дополнительный запуск на неизменённом frontend сообщает 214 замечаний, преимущественно распознавая Ant Design Form.Item как самостоятельные формы. Изменения CRM в задачу не входят.
- `git diff --check`: успешно.

Схема БД не менялась, миграция и генерация Prisma Client не требуются. Ранее существовавшие неотслеживаемые отчёты не включены в коммит.
