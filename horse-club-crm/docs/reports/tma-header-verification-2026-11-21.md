# Проверка шапки Telegram Mini App · 21.11.2026

Исправлены верхний safe area и ролевые переключатели в `frontend/src/tma`.
Отступ: 20px + max(env safe area, Telegram system safe area) + Telegram content safe area.
Изменения inset синхронизируются по `safeAreaChanged` / `contentSafeAreaChanged`.
Администратор без привязки к тренеру видит только расписание клуба; тренер и администратор с привязкой могут переключаться между личным и общим расписанием, сохраняя выбранную дату.

Проверки выполнялись через `npm.cmd` из-за политики запуска PowerShell:

- frontend: `run typecheck`, `run lint`, `run build`, `test` — успешно, 191 unit-тест.
- backend: `run typecheck`, `run lint`, `run build`, `test` — успешно, 850 тестов, 26 пропущены; линтер выдаёт три существующих предупреждения в серверных тестах.
- `npm.cmd --prefix frontend run test:e2e -- --config=playwright.tma.config.ts` — 18/18 успешно.
- Playwright: основной viewport 390×844, проверены также ширины 360 и 430; ФИО находится ниже верхней границы минимум на 20px, целиком помещается в viewport; нет горизонтального переполнения и вертикальной прокрутки пустого расписания. Проверены ненулевые SDK inset, оба события обновления, администратор без тренера и сохранение дня в обоих ролевых вариантах переключения.
- Скриншот `test-results/tma-safe-area-true.png` просмотрен: ФИО полностью видно, шапка и календарь помещаются по ширине.
- Общий strict UI-аудит: 247 замечаний вне изменённых компонентов; сохранён `docs/reports/tma-header-ui-audit.json`. Он не является успешной проверкой всего UI репозитория.

Схема БД не менялась, Prisma generate и миграции не требуются. Проверки выполнены в браузере с mock Telegram SDK; физический Telegram WebView не проверялся.
