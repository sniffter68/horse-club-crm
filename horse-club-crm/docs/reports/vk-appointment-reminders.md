# Автоматические VK-напоминания — 08.11.2026

`VkReminders` проверяет записи при запуске и каждые 10 минут через
`@Cron(CronExpression.EVERY_10_MINUTES)`. `ScheduleModule.forRoot()` подключён
однократно в `AppModule`, таймзона планировщика и текста — `Europe/Moscow`.
Подключение соответствует [документации NestJS](https://docs.nestjs.com/techniques/task-scheduling).

Окна включают обе границы: 23,5–24,5 часа и 1,5–2,5 часа от текущего момента.
В существующей Prisma-схеме подтверждённая запись имеет статус `scheduled`
(статуса `CONFIRMED` нет). Выбираются только такие записи с `PENDING` и
заполненным VK ID клиента; для групповых занятий учитываются текущее время,
тренер и статус связанного `Lesson`.

Используется существующая таблица `VkNotification`. Уникальный ключ включает
тип напоминания, ID записи, время занятия и VK ID. Старые ключи `reminder24h`
совместимы. Миграция и генерация Prisma Client не требуются.

Отправка выполняется существующим `VkNotifications` через VK API: метода
`VkBotService.sendMessage` в репозитории нет. Перед отправкой повторно
проверяются отмена, перенос, начало занятия и привязка клиента.
Атомарный `updateMany` фиксирует `attemptCount = 1` до обращения к VK:
два обработчика не отправят одно напоминание повторно. Ошибка, включая VK 901,
логируется через `Logger.warn`, другие получатели продолжают обрабатываться.
Неудачные напоминания сохраняются с `sentAt = null` и не повторяются.
Обычные уведомления сохраняют прежние повторные попытки.

Это семантика одной попытки: при аварии процесса между фиксацией попытки и
вызовом VK напоминание не будет автоматически отправлено повторно.
Отправка реальным клиентам при проверках не выполнялась.
