# Карта денников

Раздел «Лошади и постой → Карта денников», маршрут `/stable`. Использует существующую сущность `Stall`; договоры постоя и их история сохраняются.

## Установка

Из `backend` выполните `npx prisma migrate deploy` и `npx prisma generate`, затем перезапустите backend. Миграция `20261016090000_stall_map` создаёт 12 денников основной конюшни и 4 летника **только если таблица пуста**. `prisma/seed.cjs` также инициализирует пустую таблицу.

Существующим денникам миграция назначает номера и позиции по порядку создания. Это техническое начальное расположение: его необходимо сверить с реальной конюшней через редактор денника. Текущие активные договоры импортируются как физическое размещение только при однозначной связи денника и лошади; неоднозначные случаи остаются для ручного размещения. Пол и год рождения вводятся в карточке лошади; неизвестный пол не считается мерином и не порождает предположений.

## API и правила

- `GET /api/stalls`: существующий пагинируемый каталог Refine, дополненный лошадью, владельцем, рационом и `warnings`. Соседство вычисляется по всей конюшне, независимо от страницы.
- `GET /api/stalls/map`: полная схема, лошади с владельцами и рационами, предупреждения; финансовые данные договоров в карту не включаются.
- `GET /api/stalls/assignment-horses`: список ID/кличек для заселения и переселения, ADMIN/MANAGER.
- `POST /api/stalls`, `PATCH /api/stalls/:id`: номер, корпус, сторона, позиция, статус, заметки. Старые `name`, `description`, `isUnavailable` сохранены. Для старых клиентов координаты могут отсутствовать; такие денники отображаются отдельной группой без проверки соседства.
- `PATCH /api/stalls/:id/assign`, `{ "horseId": "uuid" }` или `{ "horseId": null }`: заселение, переселение, выселение. Только ADMIN/MANAGER; TRAINER читает карту, рацион и печатает таблички. Действует также существующее разрешение `boardingAccess`.

Нельзя заселить ремонтный, карантинный или уже занятый другой лошадью денник. Для смены жильца сначала уберите текущую лошадь. Чтобы перевести занятый денник в ремонт/карантин, сначала освободите его. `OCCUPIED` устанавливается назначением, а не ручным изменением статуса. Ремонт/карантин синхронизируются с прежним флагом недоступности.

Переселение освобождает старый денник и обновляет прежнее поле `Horse.stallNumber` в одной SERIALIZABLE-транзакции с ограниченным повтором конфликтов. База обеспечивает уникальность лошади, номера в корпусе и координат, согласованность статуса с заселением. Физическое размещение не меняет финансовые договоры, начисления или их исторический `stallId`.

Предупреждения симметричны: жеребец/кобыла и жеребец/жеребец в соседних элементах отсортированного ряда либо строго напротив в одном корпусе. Пустые денники разделяют лошадей. Поддерживаются последовательные позиции внутри ряда и нумерация 1/3/5 слева, 2/4/6 справа. В последнем случае №1 и №3 смежные, №1 и №2 напротив; API возвращает `rowPosition` для выравнивания карты. Диагональные денники и другие корпуса исключены. Предупреждение не блокирует сохранение.

## Быстрый перевод и рокировка (2026-10-22)

В шторке занятого денника ADMIN/MANAGER выбирает «Перевести в денник». Ant Design Modal/Select показывают свободные денники первыми, занятые — с пометкой «Рокировка с [кличка]». Ремонтные и карантинные денники исключены. Перед подтверждением сервер рассчитывает предупреждения для обоих новых мест. Ошибка сохраняет выбор; повтор доступен, двойная отправка блокируется. READ_ONLY не видит действие.

- `POST /api/stalls/transfer/preview`: `{sourceStallId, targetStallId, horseId, swapIfOccupied}` возвращает предупреждения без записи.
- `POST /api/stalls/transfer`: тот же DTO переводит лошадь или атомарно меняет двух лошадей местами. Необязательный `expectedTargetHorseId` (UUID или `null` для пустого денника) защищает выбор от изменения жильца другим пользователем.

Оба эндпоинта проверяют UUID, роль и доступ STABLES/boardingAccess. SERIALIZABLE-транзакция проверяет исходное размещение, доступность целевого денника, обновляет обе связи и `Horse.stallNumber`, сохраняет `StallTransferLog` с actorId, временем и ID участников. Сбой аудита откатывает размещение. Финансовые договоры не меняются. Требуется миграция `20261022120000_stall_transfer_audit` и генерация Prisma Client.

Бейдж «Риск соседства» показывает в Ant Design Tooltip все причины при наведении и фокусе карточки с клавиатуры. Сообщения API содержат клички обеих лошадей и различают жеребцов напротив и рядом. Для корпуса или статуса `QUARANTINE` дополнительно выводится «Карантинная зона», включая пустые денники.

Печать открывает доступный TRAINER предпросмотр таблички и системную печать. CSS скрывает остальной интерфейс, сохраняет многострочные заметки и делит существующий текст рациона по Утро/День/Вечер/Сено/Подкормки. Произвольный текст рациона не теряется. Отсутствующие данные явно подписаны.

## Проверка

`npm --prefix backend test`, `npm --prefix frontend test`, `npm --prefix frontend run lint`, обе сборки и `npm --prefix frontend run test:e2e:mock`.

`npm --prefix backend run test:stalls:postgres` создаёт и удаляет временную локальную базу, применяет все миграции и запускает тесты. Если роль не имеет CREATEDB, установите `STALL_TEST_SCHEMA_ONLY=1`: тогда создаётся и удаляется только отдельная схема `cash_desk_check_stalls_<timestamp>` в настроенной локальной БД. Основная схема приложения не изменяется. `STALL_TEST_PORT` позволяет указать порт локального PostgreSQL. Тесты, требующие специального имени отдельной базы (`RUN_TRIAD_TESTS`), в режиме схемы остаются пропущенными.

Unit/HTTP: `backend/test/stall-map.test.cjs`. PostgreSQL: `backend/test/stall-map.postgres.test.cjs`. Браузерные сценарии: `frontend/e2e/stall-map.spec.ts`, включая права, переселение, ошибки, печать, узкий экран, клавиатуру, фильтр и сохранение заметок.
