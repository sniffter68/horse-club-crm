# Персонал, смены и зарплата

Раздел `/staff` объединяет график смен, табель и ставки. Профиль связан с учетной записью User; ФИО и должность задаются отдельно, поэтому модуль подходит и сотрудникам без карточки тренера. Доступная в проекте роль TRAINER используется для личного кабинета сотрудника. Пользователя сначала создает ADMIN в разделе «Пользователи», затем ADMIN или MANAGER добавляет профиль в настройках ставок.

## Правила расчета

- Все даты — календарные дни Europe/Moscow; границы периода включены. В БД смены и периоды хранятся как DATE. Для выборки Lesson используются московская полночь начала и исключающая полночь следующего дня после конца периода.
- Начисляются только смены COMPLETED и занятия Lesson.COMPLETED, начавшиеся в периоде. SCHEDULED, ABSENT и SICK не дают оплаты за смену.
- Ставка за занятие начисляется один раз за Lesson. Два и более действующих участника означают групповую ставку; если она не задана, используется индивидуальная. Процент начисляется дополнительно к фиксированной ставке от суммы сохраненных Booking.costAmount участников со статусом scheduled/completed. Отмены и неявки исключены. Завершение Lesson в существующем расписании не меняет статус Booking, поэтому scheduled также учитывается у завершенного Lesson. Актуальная цена Service не подменяет сохраненную стоимость записи.
- Процент округляется до копеек отдельно для каждого занятия (Decimal, ROUND_HALF_UP). Итого = смены + занятия + премии − удержания. Отрицательная итоговая сумма не сохраняется, нулевая ведомость сохраняется без выплаты.
- Смена ограничена одним календарным днем, начало раньше конца; одна смена на сотрудника в день. Для пакетного планирования выбираются до 31 уникальной даты. Конфликт одной даты откатывает весь пакет. Завершить будущую смену нельзя.
- Preview GET не изменяет данные. Сохранение расчета фиксирует премии и удержания; неоплаченные суммы пересчитываются из текущих ставок и фактов. Клиент передает expectedUpdatedAt, чтобы не перезаписать изменение другого пользователя; null означает отсутствие сохраненной ведомости.
- Перед выплатой сервер заново рассчитывает суммы и сверяет их с сохраненной ведомостью и expectedTotal. Изменение суммы требует обновить и сохранить расчет.
- Выплаченный расчет — неизменяемый снимок сумм. Его смены нельзя исправить или удалить. Повторная или пересекающаяся выплата за того же сотрудника запрещена. Неактивные профили остаются в табеле для расчета прошлой работы, но новые смены для них недоступны.

## Касса и транзакция

Выплата в Serializable-транзакции создает Expense(category=SALARY), связывает его с PayrollCalculation и устанавливает isPaid/paidAt. Расход получает автора из JWT, открытую кассовую смену автора, способ CASH или CARD и описание с ФИО и периодом. Балансы в FinanceService рассчитываются по операциям в БД: CASH уменьшает наличный остаток, CARD — безналичный. Отдельного кэша баланса нет.

Advisory lock по сотруднику и повтор транзакций при конфликте сериализации защищают одновременные выплаты. Повтор POST с тем же calculationId, способом и суммой возвращает результат без нового расхода, в том числе после потери HTTP-ответа. Другой способ/сумма дают 409. Отмена связанного зарплатного расхода через кассу запрещена, чтобы не рассогласовать ведомость с остатками. Автоматических внешних банковских переводов нет: фиксируется расход CRM.

## API

Все маршруты требуют JWT. ADMIN/MANAGER управляют профилями, сменами, начислениями и выплатами. TRAINER читает только свой профиль, график и начисления; чужой staffId дает 403, управление недоступно. Удаление смен — только ADMIN.

| Метод | Маршрут | Данные |
|---|---|---|
| GET | `/api/staff` | staffId?, page?, pageSize?; `{ data, total }` |
| GET | `/api/staff/candidates` | учетные записи без профиля, до 500; ADMIN/MANAGER |
| POST | `/api/staff` | userId, fullName, roleTitle, shiftRate?, lessonRate?, groupLessonRate?, lessonPercentage?, isActive? |
| PATCH | `/api/staff/:id` | изменяемые поля профиля; userId нельзя менять |
| GET | `/api/staff/shifts` | from, to, staffId?, status?, page?, pageSize?; `{ data, total }` |
| POST | `/api/staff/shifts` | staffId, date **или** dates[], startTime, endTime, notes? |
| PATCH | `/api/staff/shifts/:id` | status?, startTime?, endTime?, notes? |
| DELETE | `/api/staff/shifts/:id` | ADMIN, неоплаченная смена |
| GET | `/api/payroll/calculate` | from, to, staffId?, page?, pageSize?; `{ data, total }` |
| POST | `/api/payroll/calculations` | staffId, from, to, bonuses, penalties, expectedUpdatedAt? |
| POST | `/api/payroll/payout` | calculationId, paymentMethod: CASH/CARD, expectedTotal |

Период ограничен 366 днями, pageSize — 100. Пустые query-фильтры игнорируются, числа преобразуются через class-transformer @Type. Неизвестные поля тела отклоняет глобальная ValidationPipe. Денежные значения в JSON-ответах — десятичные строки.

## Интерфейс

График загружает до 10 сотрудников на страницу и все смены каждого за месяц (до 31), поэтому сетка не обрезается пагинацией смен. На desktop столбцы дней прокручиваются внутри таблицы, имена закреплены. На телефоне — общий ResponsiveTable с карточками. Вкладка, месяц, период и страница хранятся в URL. Формы, ошибки, подтверждения закрытия и удаления используют общие Ant Design и StableEntryModal; персонал передает свой набор ресурсов для инвалидации. Неопределенный исход выплаты сохраняет диалог и calculationId для безопасного повтора.

## Проверки и установка

```powershell
npm.cmd --prefix backend run build
npm.cmd --prefix backend test
npm.cmd --prefix frontend run lint
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
python scripts/audit-ui.py . --mode strict

# Изолированная локальная схема PostgreSQL; рабочие данные не затрагиваются.
$env:STAFF_TEST_PORT='5432' # если локальный порт отличается от backend/.env
$env:STAFF_TEST_BROWSER='1' # дополнительно Playwright; frontend должен работать на 5173
npm.cmd --prefix backend run test:staff:postgres

# Применить миграции к выбранной рабочей базе при развертывании.
cd backend
npx.cmd prisma migrate deploy
npx.cmd prisma generate
```

Тест PostgreSQL проверяет расчет по фактическим записям, откат после вставки расхода, конкурентные повторы, CASH/CARD, оплаченные периоды и приватность. Live Playwright проверяет планирование/завершение смены, премию и удержание, выплату с потерей ответа и безопасным повтором, появление расхода и изменение остатка, создание/редактирование ставок, ошибки формы, мобильный личный кабинет и темную тему. Миграция `20261018150000_staff_payroll` проверяется тестовым runner на одноразовой схеме, рабочая база автоматически не мигрируется.
