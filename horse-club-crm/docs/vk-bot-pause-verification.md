# Режим тишины VK-бота

Дата проверки: 01.11.2026.

## Поведение

- Ручной исходящий ответ сообщества (`message_reply`) сохраняет паузу диалога на два часа в `VkConversationState`, ключ — `peerId`.
- Исходящие сообщения API с ненулевым `random_id` не включают паузу. Бот и очередь уведомлений уже используют ненулевые идентификаторы.
- «Позвать администратора» в меню гостя и клиента включает паузу на четыре часа, использует существующую очередь уведомлений для `VK_ADMIN_PEER_ID` и отправляет подтверждение с inline-кнопкой возврата.
- Пока срок паузы не истёк, входящие сообщения и старые кнопки меню не вызывают автоматический ответ. «Меню», `/start` и payload `RESET_BOT_PAUSE` сбрасывают паузу и возвращают меню роли пользователя.
- После истечения срока следующее входящее сообщение очищает паузу и обрабатывается как обычно. Состояние хранится в PostgreSQL и сохраняется после перезапуска backend.

## Настройка и миграция

В настройках Callback API сообщества нужно включить событие **message_reply** вместе с `message_new` и `message_event`. Проверка подключения теперь напоминает обо всех трёх событиях. Для оповещения администратора используется существующая настройка **VK_ADMIN_PEER_ID**; при её отсутствии или ошибке очереди причина записывается в журнал.

Нужна миграция `20261101180000_vk_bot_pause`. Prisma Client 6.19.3 сгенерирован локально. `prisma migrate deploy` выполняется на сервере штатным процессом деплоя; локальная БД не изменялась.
