# Ревизия статического UI-аудита

Дата: 24.11.2026. Область: `frontend/src`, существующий Ant Design 5 и runtime-тема Horse Club OS. Бизнес-правила, API, RBAC и схема Prisma не менялись.

## Исходные 263 замечания

| Правило / фактический JSX | До | Реальных дефектов по этому правилу | Известных ложных срабатываний после |
| --- | ---: | ---: | ---: |
| `form.novalidate-missing`: `Form.Item` | 215 | 0 | 215 |
| `form.novalidate-missing`: `<Form<T>>` с `noValidate` | 6 | 0 | 6 |
| `ownership.native-select-conflict`: Ant Design `Select` | 42 | 0 | 42 |
| **Всего** | **263** | **0** | **263** |

`Form.Item` создаёт обёртку поля, а не HTML-форму. У generic JSX HTML-парсер обрывает открывающий тег на `>` аргумента типа и не видит следующий `noValidate`. Ant Design `Select` — канонический authored combobox проекта; это не нативный `<select>`. AST-проверка подтверждает импорты из `antd`, конкретный JSX и наличие `noValidate` у **всех 32 настоящих форм**. Добавлять этот атрибут к `Form.Item` или менять Ant Design на нативные контролы не требуется.

Исходный скрипт навыка не изменён; правила и ownership не отключены. Его strict exit code остаётся **1**, потому что он повторно выдаёт те же 263 ложных замечания. Отдельная классификация завершается с **0**: непросмотренных замечаний и настоящих форм без `noValidate` нет.

Артефакты: [до](ui-audit-before.json), [после](ui-audit-after.json), [классификация исходного кода HEAD](ui-audit-before-classified.json), [полная классификация результата](ui-audit-classified.json). Каждая запись содержит файл, строку, JSX-тип и объяснение.

## Дополнительные реальные дефекты

Эти проблемы найдены проверкой TypeScript/DOM и браузером; исходные два правила их не обнаруживают. Числа ниже обозначают независимые причины, а не количество затронутых экземпляров компонента.

| Категория | Исправлено | Исправление |
| --- | ---: | --- |
| Связи полей, подписи и ошибки | 4 | `HorseSexSelect` передаёт `id`/ARIA от `Form.Item`; `LiveSearch` передаёт `id` в AutoComplete и атрибуты ошибок в Input; оба поля периода журнала и времени смены имеют доступное имя |
| Локализация | 1 | RangePicker журнала использует `ru_RU`, включая подсказки начальной/конечной даты |
| Мобильное переполнение | 1 | Popup периода выходил до x=714 при ширине 390 px; панели теперь вертикальные, popup внутри экрана, высота ограничена, прокрутка изолирована |
| Контраст тёмной темы | 2 | Текстовые роли отделены от сплошных заливок; active primary button больше не получает почти белый фон при белом тексте |
| Консистентность цветов | 1 | Расписание/журнал используют общие `crm-tag`; события, нагрузка и предупреждения используют CSS-переменные вместо повторяющихся hex |
| **Всего дополнительных причин** | **9** | **Все перечисленные причины устранены** |

Новые семантические имена ссылаются на прежнюю палитру: `--crm-success`, `--crm-warning`, `--crm-danger`, `--crm-on-solid`, `--crm-text-secondary`, `--crm-text-accent`. Светлые цвета сохранены. Фиксированные контрастные пастельные пары общих бейджей, белая печатная табличка, определения Ant Design/entryDrawerTheme и пользовательский цвет тренера оставлены намеренно: это источники темы или доменные данные, а не забытые inline-цвета.

Контраст телефона в тёмной карточке: **2,20:1 → 11,93:1**, в светлой — **7,48:1**. Вторичный текст на тёмной карточке: **2,89:1 → 9,13:1**. Для телефона проверяется фактическая пара из computed styles; значения вторичного текста рассчитаны из runtime-токенов. Внутри пастельных бейджей числовой текст наследует цвет бейджа.

Новых проблем с отступами и блокировкой отправки в проверенных сценариях не подтверждено: `StableEntryModal`, `CatalogDrawerForm` и формы расписания уже используют busy/loading, блокировку повторного запроса и сохранение значений после ошибки. Эти механизмы не переписывались.

Расширенный прогон проверяет также 320/390/1440 px, неудачное сохранение и повтор, read-only, сохранение слота, optimistic rollback и закрытые даты смен. Это целевая проверка изменённых контрактов, не заявление о полном WCAG-аудите всех состояний приложения.

Известное ограничение: `live-search.spec.ts` не открывает карточку клиента после выбора подсказки на 1280 и 390 px. При временной подстановке **исходного LiveSearch из HEAD** оба сценария падают на той же проверке; текущий файл после проверки восстановлен побайтно. Лог: [ui-audit-search-baseline.log](ui-audit-search-baseline.log). Это отдельная существующая проблема навигации/URL-состояния, не замечание двух правил статического аудита; механизм навигации не менялся в этой ревизии. Полностью зелёный расширенный E2E-прогон не заявляется.

В PowerShell использован `npm.cmd`: системная execution policy блокирует `npm.ps1`. Миграции БД и `prisma generate` не требуются.

## Воспроизведение

Путь `<skill>`: установленный `frontend-design-premium/1.4.0/skills/frontend-design-premium`.

```powershell
python <skill>/scripts/audit_project.py . --mode strict --output docs/ui-audit-after.json
node scripts/classify-ui-audit.ts docs/ui-audit-after.json docs/ui-audit-classified.json
npm.cmd --prefix frontend run lint
npm.cmd --prefix frontend run typecheck
npm.cmd --prefix frontend run build
npm.cmd --prefix frontend test
# При запущенном frontend dev server:
$env:CRM_TEST_BASE_URL='http://127.0.0.1:5174'
node frontend/node_modules/playwright/cli.js test --config frontend/playwright.ui-audit.config.ts
```

Исходную классификацию можно воспроизвести с `--git-head`, пока HEAD соответствует исходному состоянию этой ревизии. Скрипт намеренно завершится с ошибкой при неизвестном новом finding или форме без явного `noValidate`; это не универсальный allowlist Ant Design.
