# Прямая привязка VK

Администратор указывает числовой ID, `id12345678`, `@username` или ссылку `vk.com/username` в карточке клиента, сотрудника или пользователя. Пустое поле снимает привязку. Телефон и коды подтверждения для привязки не используются; прежний маршрут `/vk/link-codes` больше не зарегистрирован.

Короткие имена разрешаются в числовой ID до записи через `users.get` VK API 5.199. Требуется существующий `VK_COMMUNITY_TOKEN` (допускается прежний `VK_BOT_TOKEN`). Числовой ID сохраняется без внешнего запроса. Источник контракта VK: https://github.com/VKCOM/vk-api-schema/tree/master/users.

`PATCH /api/clients/:id` принимает `vkId` и `vkScreenName`, `PATCH /api/users/:id` — `vkId`. Ввод `null` или пустой строки снимает связь. В форме персонала поле сохраняется вместе с профилем в одной транзакции; владельцем связи является `User`. Для привязки из списка тренеров нужна связанная учетная запись `User.trainerId`.

Один VK ID не может принадлежать разным клиентам/сотрудникам. Проверяются и старые поля доставки `vkUserId`; запись выполняется в Serializable-транзакции с повтором при конфликте сериализации. Конфликт уникальности возвращает HTTP 409. При смене аккаунта удаляются неотправленные персональные уведомления прежнему получателю. Поля `vkUserId` синхронизируются с `vkId` для существующих отправителей напоминаний и отметок посещения.

`GET /api/vk/identify?vkId=12345678` требует заголовок `x-bot-token`, равный отдельному секрету `VK_IDENTIFY_TOKEN`. Секрет задается в серверном `.env` и передается контейнеру backend. Пустой секрет закрывает эндпоинт (503), неверный возвращает 401. Токен сообщества не используется как сервисный секрет. Токен не должен попадать во фронтенд.

Ответы: `STAFF` с `role`, `name`, `staffId` (ID User), `trainerId`; `CLIENT` с `clientId`, `name`, `activeMembershipsCount`, `nextBooking`; либо `UNKNOWN`. Сотрудник имеет приоритет. Архивные клиенты и неактивные сотрудники не получают персонального меню. Встроенный webhook использует тот же `VkIdentityService.identify` напрямую, без HTTP-запроса к собственному серверу и без необходимости сервисного секрета. Внешний бот использует защищенный GET.

Бот открывает клиенту баланс, тренировки и запись через администратора; тренеру — расписание и всадников на сегодня, с действующими отметками посещения. Гость получает приглашение и контакты из `VK_CLUB_*`. Телефон может запрашиваться для новой заявки с отдельным согласием; он не используется для идентификации или привязки.

Миграция `20261026120000_vk_direct_identity` добавляет поля и индексы, переносит существующие связи клиентов и пользователей, включая привязанных к учетным записям тренеров. Для тренера без учетной записи сначала необходимо связать `User.trainerId`. На сервере применяется `prisma migrate deploy`; локальное применение не требуется. Prisma Client необходимо генерировать при сборке образа.
