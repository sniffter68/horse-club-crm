# Удаление и архив лошадей

`DELETE /horses/:id` выполняет решение в Serializable-транзакции с блокировкой строки лошади, совместимой с записью занятий. Отсутствующая или архивная лошадь возвращает 404. Будущие и текущие незавершённые занятия и договор постоя `ACTIVE` блокируют удаление с понятным 409. Отменённые записи и архивные занятия не блокируют операцию.

История в `bookings`, `boardingContracts`, `vetRecords`, `vetEvents`, `healthLogs` или `dailyLogs` приводит к архивированию: `deletedAt` заполняется, `isUnavailable=true`, `isPublic=false`. Исторические связи и финансовые документы сохраняются. Без этих связей запись удаляется физически. В обоих случаях сбрасываются предпочтения клиентов и освобождается денник; `stallNumber` у архивной лошади очищается. При конкурентном изменении транзакция откатывается, API предлагает повторить действие.

`GET /horses` исключает архив по умолчанию; `includeArchived=true` добавляет архивные записи. `GET /horses/:id` сохраняет доступ к архивной карточке. Редактирование архивной лошади и новое назначение на занятие или постой запрещены. Исторические включения лошадей в занятия и отчёты не фильтруются. Рабочие списки, доступность, замены, денники, Telegram/TMA и публичный API исключают архив.

Интерфейс использует существующий `CatalogList` и подтверждение `DeleteButton`. Фильтр «Показать архивных» выключен по умолчанию. Карточка показывает «Лошадь в архиве», историю и убирает действия изменения статуса и нового постоя. Прямая ссылка: `/horses?horseId=<UUID>`. Кнопки мутаций по-прежнему подчиняются общим правам модуля.

## Миграция

Перед запуском обновлённого API применить на сервере из `backend/`:

```sh
npx prisma migrate deploy
npx prisma generate
```

Миграция: `20261122120000_add_horse_soft_delete`, поле `Horse.deletedAt TIMESTAMPTZ(6)` и индекс. Локальный `prisma migrate dev --name add_horse_soft_delete` завершился ошибкой schema engine на подключении `127.0.0.1:5433`; SQL подготовлен вручную, Prisma Client 6.19.3 успешно сгенерирован. Проверка миграции на настоящем PostgreSQL остаётся обязательной при развёртывании.

## Проверки

- `backend/test/horse-soft-delete.test.cjs`: физическое удаление, все шесть видов истории, освобождение денника и предпочтений, 404, HTTP 409, фильтр и прямой GET архивной карточки.
- `backend/test/booking-rules.test.cjs`: запрет назначения архивной лошади по UUID даже с устаревшими флагами доступности.
- `backend/test/workspace.test.cjs`: архив исключён из ресурсов trainer-board, сохранён в истории занятия.
- `frontend/src/providers.test.ts`: передача, очистка и валидация архивного фильтра.
- `frontend/e2e/horse-archive.spec.ts`: 409 и повтор, удаление, фильтр с клавиатуры, архивная история и прямая ссылка на ширине 1280 и 390 px.
