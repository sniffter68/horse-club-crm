# VK Callback API и ролевые меню

Основной адрес: `https://crm.horseclub68.ru/api/vk/callback`. Сохранены алиасы `/api/vk/webhook` и `/api/vk-bot/callback`. Все проверяют секрет, а при заданном ID — сообщество. `confirmation` возвращает строку; `message_new` и `message_event` получают `ok`, не ожидая БД или VK. Ошибки фоновой обработки логируются без тела события и секретов. Обработка в памяти: при аварийном перезапуске уже подтверждённое событие может быть потеряно; долговечная входящая очередь в этот релиз не входит.

Предпочтительные переменные: `VK_COMMUNITY_ID`, `VK_ACCESS_TOKEN`, `VK_CONFIRMATION_TOKEN`, `VK_SECRET_KEY`. Они имеют приоритет над `VK_GROUP_ID`, `VK_GROUP_TOKEN` / `VK_COMMUNITY_TOKEN` / `VK_BOT_TOKEN`, `VK_CONFIRMATION_CODE`. Docker передаёт обе группы имён. Не заменяйте действующие секреты примерами из документации.

В настройках CRM доступна вкладка «Интеграция VK» только для ADMIN. GET `/api/settings/vk` отдаёт признаки наличия ключей, но не значения. PATCH сохраняет настройки; пустые поля ключей оставляют прежние значения. POST `/api/settings/vk/check` проверяет введённый токен сообщества, разрешение messages и соответствие ключа подтверждения, не сохраняет черновик и не отправляет сообщений. Проверка токена не доказывает доставку webhook: в VK нужно подтвердить адрес и включить `message_new`, `message_event`.

Настройки шифруются AES-256-GCM в `VkIntegrationSettings`, с идентификатором изменившего администратора. Ключ выводится из серверного `JWT_SECRET` с отдельным контекстом. Он должен сохраняться при перезапуске; перед его сменой потребуется перенастроить интеграцию. Сохранённые настройки имеют приоритет над окружением и загружаются при старте. После изменения перезапуск не нужен; транспорт бота и доставки обновляется сразу. Расчёт рассчитан на один экземпляр backend, как в текущем Docker Compose.

Гость получает запись на реальную форму `https://horseclub68.ru/#booking-form`, публичные цены CRM, привязку, помощь и контакты. Клиент — предстоящие тренировки с тренером и назначением/статусом лошади, активные личные и семейные абонементы, запись, баланс постоя и последние пять оплаченных квитанций. Это личные данные клиента, а не общий баланс кассы. Тренер — своё расписание на сегодня/завтра, лошадей в работе сегодня и всадников. Границы дней и все даты — Europe/Moscow. Отметки посещения сохраняют существующий сервис финансового учёта.

Прямая привязка администратором в карточке CRM сохранена. Дополнительно возвращён ADMIN/MANAGER endpoint POST `/api/vk/link-codes` с `{kind: "CLIENT" | "TRAINER", id: UUID}`. Администратор передаёт код владельцу профиля; тот пишет боту `привязать +79991234567 1234`. Код действует пять минут и связан с телефоном CRM; пять неудачных попыток блокируют VK-отправителя на 15 минут. Для тренера требуется связанная учётная запись. Проверяются занятость VK ID и архив; оба поля `vkId` / `vkUserId` обновляются в одной serializable-транзакции. POST `/api/vk/link-codes/unlink` отзывает связь и ожидающие уведомления. Привязка по одному непроверенному номеру не выполняется, чтобы не раскрыть чужие данные. Используется текстовый ввод: `request_contact` отсутствует среди поддерживаемых действий в официальной схеме VK API 5.199: https://github.com/VKCOM/vk-api-schema/blob/master/messages/objects.json.

Миграция: `20261101120000_vk_integration_settings`; Prisma Client сгенерирован локально. На production её применяет существующий migrate-сервис при деплое. Локальный migrate deploy не требуется.

Проверки: `backend/test/vk-finalization.test.cjs`, обновлённые VK-тесты, `frontend/e2e/vk-settings.spec.ts` и `vk-link.spec.ts`. Дополнительный статический premium-аудит всего проекта фиксирует прежние замечания и ложные совпадения `Form.Item` как отдельных HTML-форм; настоящая форма новой вкладки использует `noValidate` и Ant Design Form. Этот аудит не считается пройденным и не заменяет браузерные проверки.

## Отчёт проверки 01.11.2026

- backend/frontend: typecheck, Oxlint, production build — успешно; backend Oxlint сообщает три прежних предупреждения в тестах вне VK.
- backend: 624 passed, 20 skipped (интеграционные проверки с отдельной БД/окружением), 0 failed; из них 8 новых проверок финализации VK.
- frontend: 16 файлов, 154 unit-теста успешно.
- Playwright mock: 8 сценариев VK успешно, включая desktop/320px, настройки/390px, клавиатуру, ошибки, запрет доступа, dark/reduced motion.
- Prisma Client 6.19.3 сгенерирован. Изменение версии Prisma не выполнялось.
- Статический premium-аудит: 207 замечаний по проекту; в новой вкладке два ложных совпадения на `Form.Item`. Общий аудит не пройден; остальные замечания вне области VK. Браузерные сценарии новой вкладки пройдены.
- Живая отправка сообщений и подтверждение сервера со стороны VK не имитируются тестовым сообщением в реальном сообществе. Для этого нужны действующие настройки сообщества.
