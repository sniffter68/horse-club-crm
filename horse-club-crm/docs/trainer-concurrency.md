# Одновременные занятия одного тренера

Решение владельца от 05.11.2026: тренер может вести нескольких независимых всадников на разных лошадях. Профиль Trainer содержит `maxParallelLessons`: целое число от 1 до 100, по умолчанию 4. Поле редактируется в существующей форме тренера и доступно через POST/PATCH `/trainers` с прежними правами SCHEDULE. Установка 1 возвращает индивидуальную вместимость.

`BookingRulesService` проверяет пиковое количество одновременных всадников на полуоткрытом интервале `[start, end)`. События окончания обрабатываются перед событиями начала. Прямое бронирование занимает одно место, Lesson — число его Booking-участников (пустой Lesson резервирует одно место). Копии Booking внутри Lesson не учитываются второй раз. Для замены лошади учитываются остальные участники исключённого Lesson. Отменённые записи и удалённые Lesson не занимают места. Проверка общая для создания, переноса, замены лошади и конвертации заявки. Ошибка 409 `TRAINER_BUSY`: «У тренера достигнут максимум одновременных всадников (N)» с `details.maxParallelLessons`.

Пересечения клиента и лошади остаются строгими. Вместимость манежа проверяется по существующему `maxRidersCapacity` и пиковому числу всадников. Транзакции Serializable, блокировки ресурсов и повторные проверки при конкуренции сохраняются. Каждый Lesson и Booking остаётся отдельной записью со своим клиентом, абонементом, стоимостью и платежами; финансовые обработчики не меняются.

Создание через общий LessonDrawer и редактирование через TriadBookingModal показывают занятость/свободные места тренера. При достижении лимита сохранение блокируется. Данные загружаются для выбранного интервала независимо от фильтров расписания; редактируемая запись исключается. При ошибке загрузки отображается предупреждение и неизвестная занятость, сервер повторно проверяет запрос. После 409 доступность обновляется. Карточки расписания сохраняют существующие отдельные колонки, а заголовок тренера показывает пик загрузки за день.

## Развёртывание

До запуска обновлённого backend применить на сервере `npx prisma migrate deploy`. Миграция `20261105120000_trainer_parallel_lessons` добавляет NOT NULL поле с default 4 и CHECK 1–100, сохраняя существующие занятия. Она не изменяет старые пересечения; для новых записей применяется новый лимит. Prisma Client сгенерирован локально командой `npx prisma generate`.
