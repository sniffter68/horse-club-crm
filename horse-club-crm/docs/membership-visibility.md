# Видимость неактивных абонементов

По умолчанию `/api/memberships` (и совместимый `/api/client-memberships`) возвращает только действующие абонементы. Проверяются `remainingUnits > 0`, точные границы `validFrom <= now <= validTo`, статус `active`, отсутствие `cancelledAt` и `deletedAt`. Тот же баланс и срок используются для `isActive` в списке, деталях абонемента и карточке клиента. Проверка срока не округляется до начала московского дня.

Явные фильтры:

| state | Результат |
| --- | --- |
| `active` или отсутствует | Только действующие |
| `all` | Все статусы, включая отменённые, без записей с `deletedAt` |
| `exhausted` | Остаток `<= 0`, без отменённых и архивных |
| `expired` | `validTo < now`, без отменённых и архивных |
| `archived` | Записи с `cancelledAt` или `deletedAt` |

Состояния exhausted и expired могут пересекаться: абонемент с нулевым остатком и истёкшим сроком доступен в обоих фильтрах. Замороженные и ещё не начавшиеся абонементы доступны через «Все статусы».

В CRM начальный фильтр — «Активные». Сброс очищает поиск и оплату, возвращает активный статус и отправляет форму. Выбранные статусы сохраняются Refine в URL. `dataProvider` явно допускает `all`.

Карточка клиента сохраняет полную историю в ответе API, но по умолчанию показывает только активные абонементы. `MembershipVisibility` раскрывает остальные кнопкой «Показать завершённые (N)». При смене клиента раскрытие сбрасывается.

Для выбора оплаты в расписании используется общая проверка `memberships/activity.ts`: отмена, архив, баланс, статус и срок проверяются даже при устаревшем `isActive`. Ранее привязанный завершённый абонемент больше не добавляется в варианты выбора. Каталог абонементов тренера проверяет текущее время и полный интервал занятия. Быстрая запись тренера использует этот каталог через общую форму; в текущем мастере быстрой записи отдельного выбора оплаты нет. Клиентский TMA получает только действующий абонемент через `activeTelegramMembership`.

Списание и возврат остаются транзакционными. Установленный триггер `Membership_sync_balances` синхронизирует `remainingUnits` / `remainedLessons`, `validTo` / `validUntil` и пересчитывает статус при изменении баланса. После последнего списания следующий запрос скрывает абонемент; после возврата он снова появляется, если срок действителен и нет отмены, архива или заморозки. Дополнительных фоновых заданий и миграций не требуется.

## Проверки

Серверные mock-тесты проверяют фильтрацию до пагинации, одинаковое условие подсчёта и выборки, `all` / `exhausted` / `expired` / `archived`, текущий `isActive`, валидацию DTO и последовательность последнего списания и возврата. Триггер PostgreSQL в mock-тесте моделируется; PostgreSQL-интеграционные тесты без базы пропускаются.

Frontend unit-тесты проверяют баланс, точную границу срока, отмену, архив, заморозку и восстановление активности. Playwright проверяет начальный фильтр, все явные статусы, перезагрузку URL, сброс и раскрытие завершённых с клавиатуры при ширине 1280 и 390px.

Логи команд находятся в `docs/reports/membership-visibility-*`. Дополнительный статический UI-аудит сохранён в `membership-visibility-ui-audit.json`: он сообщает общие замечания проекта и ошибочно считает Ant Design `Form.Item` и `Select` нативными формами/селектами; в изменённых формах уже используются `noValidate` и доступные библиотечные контролы.
