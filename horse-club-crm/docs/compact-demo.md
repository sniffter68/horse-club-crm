# Compact UI и демо-стенд

Изменения от 27.11.2026. Шаг рабочей области — 16px, между блоками — 12px,
в карточках — 16px, стандартная строка таблицы — 44px. Длинные значения доступны
через фокусируемый текст с подсказкой; действия строки раскрываются кнопкой
«Действия». Поиск, фильтры и создание собраны над таблицей. Сайдбар хранит
свёрнутое состояние в `horsecrm.sidebar-collapsed`.
Касса постоя открывается ссылкой в toolbar договоров; полный финансовый журнал
доступен на странице платежей и не оттесняет договоры за первый экран.

## Запуск демо

1. Создать **отдельную пустую PostgreSQL-базу** с именем, заканчивающимся на `_demo`.
2. Указать её в `DATABASE_URL`, установить `DEMO_MODE=true` и обычный `JWT_SECRET`.
3. Применить существующие миграции к этой базе: `npx prisma migrate deploy` из `backend`.
4. Запустить backend как обычно. Он автоматически инициализирует демо один раз.
   Для отдельной инициализации: `npm --prefix backend run demo-seed` (читает `backend/.env`).
5. Запустить frontend. На странице входа появятся три кнопки быстрого входа.

Новые миграции и изменения Prisma schema не требуются. Установленные миграциями
пустые стандартные денники заменяются картой демо-клуба. База с существующими
пользователями, клиентами, лошадьми или финансами не принимается за новую демо-базу.
Обычный повторный запуск сохраняет изменения посетителя. Повторный seed не создаёт дубликаты.

Учетные записи и данные вымышленные. Владелец использует системную роль `ADMIN`,
администратор — `MANAGER`, тренер — `TRAINER`. Пароли случайные, быстрый вход
проходит через отдельный проверяемый серверный endpoint и обычные HttpOnly cookies.
Не подключайте к публичному демо рабочие боты и интеграции.

## API и сброс

- `GET /api/demo/status` — публичный `{ isDemo: boolean }`.
- `POST /api/demo/login` — `{ role: "OWNER" | "ADMIN" | "TRAINER" }`, только демо.
- `POST /api/demo/reset` — авторизованный `ADMIN`/`MANAGER` с `FULL CASHBOX`.
  Возвращает `{ success: true }`; без `DEMO_MODE=true` недоступен (404).

Сброс проверяет имя базы и сохранённый маркер инициализации, получает транзакционную
блокировку, блокирует таблицы от параллельной записи, сохраняет финансовые снимки
в `CashAuditLog` с автором и временем, затем очищает таблицы и выполняет seed.
`CashAuditLog` сохраняется при каждом сбросе. Ошибка откатывает всю транзакцию.
Никаких `CASCADE` или пользовательских SQL-идентификаторов нет.

В эталоне: 10 лошадей, 10 денников, 3 тренера, 12 клиентов, 8 активных абонементов,
4 договора постоя, 14 занятий текущей недели по Москве, оплаты и расходы обеих касс.
Миграционные триггеры формируют связанные начисления и финансовые проводки.

## Проверки

- `npm --prefix backend test` — в том числе mock seed/reset, rollback, права и HTTP cookies.
- `npx playwright test --config=playwright.compact.config.ts` из `frontend` —
  заполненные таблицы семи страниц на 1366×768 и 1440×768, геометрия строк,
  отсутствие горизонтального скролла, вход, подтверждение/ошибка/повтор сброса и сайдбар.
- `RUN_DEMO_POSTGRES_TESTS=1`, `DEMO_MODE=true` и `DATABASE_URL` на изолированную
  локальную `*_test_demo` с применёнными миграциями включают
  `node --test backend/test/demo.postgres.test.cjs`.

Результаты выполнения: `docs/reports/compact-demo-verification.md`.
