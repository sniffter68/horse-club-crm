# Часы и погода в баннере смены

Проверено 19.11.2026. Поведение описано в `docs/dashboard.md`. Коды погоды сверены с [документацией Open-Meteo](https://open-meteo.com/en/docs#weather_variable_documentation).

- Frontend: `npm.cmd --prefix frontend run lint`, `run typecheck`, `run build`, `test` — успешно, 191 unit-тест в 23 файлах.
- Backend: `npm.cmd --prefix backend run lint`, `run typecheck`, `run build`, `test` — успешно, 807 тестов, 22 пропуска PostgreSQL. Линтер сохраняет 3 существующих предупреждения в других тестах.
- E2E: `npm.cmd --prefix frontend run test:e2e:mock -- dashboard.spec.ts` — изначально 37/40. Две новые проверки учитывали отменённый StrictMode-запрос как загрузку из кэша; исправлен подсчёт относительно количества запросов до перезагрузки. Один существующий сценарий выбора даты нестабильно не применил «Сейчас».
- Повторная проверка баннера и календаря (`--grep 'shift banner|dashboard date footer'`) — 7/7. Итоговый `--last-failed` — 3/3, все 40 сценариев имеют успешный результат. Сценарий календаря прошёл оба повторных запуска без изменения кода календаря.
- Проверены часы в America/New_York, обновление времени, кэш после reload и его истечение, ответы с неверными данными, HTTP 503 и заблокированный запрос; скриншоты 1440/390px просмотрены, горизонтального переполнения нет.
- Строгий `audit_project.py` сохранил `docs/dashboard-weather-audit.json`: 234 существующих замечания вне изменённых компонентов; общий аудит проекта не проходит. `git diff --check` — успешно.

Изменение схемы БД и миграции Prisma не требуются. При выкладке необходимо применить обновлённый `docker/Caddyfile`: CRM разрешает `connect-src https://api.open-meteo.com`, иначе production CSP заблокирует погоду. Конфигурация не применялась к серверу; локально нет Caddy/Docker для проверки через `caddy validate`.
