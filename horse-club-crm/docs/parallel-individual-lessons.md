# Параллельные индивидуальные занятия — 26.10.2026

Каждый запрос создания создаёт отдельный Lesson даже при совпадении тренера, услуги, манежа и интервала, независимо от `maxCapacity`. Автоматического добавления в существующие занятия нет. Группу можно создать явно, передав несколько `participants` в одном запросе в пределах вместимости услуги. Для индивидуальной услуги (`maxCapacity = 1`) допускается только один участник. Числовой лимит одновременных занятий тренера не вводится; действуют вместимость манежа и ограничения лошадей и клиентов.

Общий `BookingRulesService` разрешает пересечения тренера для обоих API записи. Лошадь и клиент остаются эксклюзивными ресурсами: ошибки 409 `HORSE_BUSY` (с кличкой) и `CLIENT_BUSY`. Проверка учитывает самостоятельные бронирования и участников занятий, включая другого тренера и манеж. Отдых, здоровье, вес, суточная нагрузка, блокировки строк и сериализуемые транзакции сохранены. Старый сервис занятий больше не блокирует тренера и манеж целиком; вместимость манежа проверяет общий модуль. GET занятий возвращает все отдельные записи.

В FullCalendar сохранён `slotEventOverlap={false}`, разрешён выбор интервала поверх существующего занятия. В сетке ресурсов `parallelLayout` раскладывает карточки по горизонтальным колонкам внутри каждого связного блока пересечений, включая вложенные интервалы и цепочки. После окончания блока карточки снова занимают полную ширину. Два занятия занимают по 50%, три — по 33,33% с зазором. Каждая карточка открывает только свой Lesson и показывает время, тренера, клиента, лошадь и оплату. Получасовой слот календаря увеличен до 84px для этих данных.

Обе формы расписания используют общие `useScheduleConflicts` и `ScheduleConflictNotice`: запросы зависят от выбранного интервала, не от фильтров и текущего диапазона календаря. Пересечение тренера показывает информационный Alert с клиентом и лошадью; пересечение выбранной лошади показывает ошибку и блокирует отправку. При редактировании текущая запись исключается. Устаревшие запросы отменяются. Сбой предварительной проверки явно отображается, сервер при сохранении повторно проверяет ресурсы.

Схема БД не изменена. Миграция и генерация Prisma Client не требуются.

Ранее объединённые групповые записи автоматически не разделяются: без отдельного переноса финансовой истории это изменило бы связь оплат, списаний абонементов и уведомлений. Новые индивидуальные записи всегда независимы. В базе участник и лошадь связаны с Lesson через его Booking; дополнительных дублирующих полей не требуется.
