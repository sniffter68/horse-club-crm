# Параллельные индивидуальные занятия — 26.10.2026

Индивидуальные услуги (`maxCapacity = 1`) создают отдельные занятия даже при совпадении тренера, услуги, манежа и интервала. Автоматическое добавление участников в существующие групповые занятия сохранено. Числовой лимит одновременных занятий тренера не вводится; действуют вместимость манежа и ограничения лошадей.

Общий `BookingRulesService` разрешает пересечения тренера для обоих API записи. Лошадь и клиент остаются эксклюзивными ресурсами: ошибки 409 `HORSE_BUSY` (с кличкой) и `CLIENT_BUSY`. Проверка учитывает самостоятельные бронирования и участников занятий, включая другого тренера и манеж. Отдых, здоровье, вес, суточная нагрузка, блокировки строк и сериализуемые транзакции сохранены. Старый сервис занятий больше не блокирует тренера и манеж целиком; вместимость манежа проверяет общий модуль. GET занятий возвращает все отдельные записи.

В FullCalendar сохранён `slotEventOverlap={false}`, разрешён выбор интервала поверх существующего занятия. В сетке ресурсов `parallelLayout` раскладывает карточки по горизонтальным колонкам внутри каждого связного блока пересечений, включая вложенные интервалы и цепочки. После окончания блока карточки снова занимают полную ширину. Каждая карточка сохраняет отдельный обработчик открытия и действия в деталях. Существующий двухстрочный вид и полная подсказка карточки сохранены.

Обе формы расписания используют общие `useScheduleConflicts` и `ScheduleConflictNotice`: запросы зависят от выбранного интервала, не от фильтров и текущего диапазона календаря. Пересечение тренера показывает информационный Alert с клиентом и лошадью; пересечение выбранной лошади показывает ошибку и блокирует отправку. При редактировании текущая запись исключается. Устаревшие запросы отменяются. Сбой предварительной проверки явно отображается, сервер при сохранении повторно проверяет ресурсы.

Схема БД не изменена. Миграция и генерация Prisma Client не требуются.
