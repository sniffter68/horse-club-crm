# Полный сброс финансовых и операционных данных

Источник: задача владельца от 28.10.2026. Это безвозвратное удаление **всех** записей перечисленных таблиц, включая архивные и боевые, если они уже появились. Автоматического определения «тестовых» записей нет. Сам деплой сброс не запускает.

## API и доступ

`POST /api/admin/reset-operational-data` — только аутентифицированный ADMIN с доступным модулем CASHBOX. Проверяются JWT, RolesGuard, ModuleAccessGuard и роль внутри сервиса.

Тело: `{ "confirmation": "RESET_ALL_OPERATIONAL_DATA", "requestId": "<UUID v4>" }`. `requestId` необязателен для API; интерфейс всегда создаёт и повторно использует его при повторе запроса. Неверное подтверждение — 400, чужая роль — 403, чужой ключ аудита — 409. Успех — 200 с `success`, `auditId`, количеством удалённых строк; повтор завершённого запроса возвращает `alreadyCompleted: true` без удаления новых данных.

## Транзакция и схема проекта

Одна Prisma-транзакция READ COMMITTED берёт общий для финансового закрытия advisory lock и эксклюзивные блокировки всех очищаемых таблиц. Ожидание блокировок ограничено 10 секундами, транзакция — 60 секундами. До удаления создаётся CashAuditLog с актором, временем и снимками финансовых строк/остатков. При любом сбое аудит и все изменения откатываются вместе.

Соответствия фактической схеме: клиентские абонементы — Membership, списания/посещения — MembershipOp/Booking, кассовые движения — Payment/Expense/LedgerTransaction, ведомости — PayrollCalculation. Отдельных Refund, PayrollItem, Cashbox и FinancialAccount нет. Возвраты находятся в Expense; остатки наличных, безналичных средств и клиентских занятий рассчитываются по финансовым строкам.

Порядок: MonthlyFinancialClosing → PayrollCalculation → LedgerTransaction → RevenueRecognition → MembershipOp → BookingHorseChange → Booking → Lesson → MembershipMember → Membership → Expense (включая возвраты) → Payment → повторная очистка LedgerTransaction/RevenueRecognition → CashShift → Client.boardingBalance = 0.00.

LedgerTransaction удаляется перед списаниями из-за RESTRICT FK. Расходы удаляются перед платежами из-за ссылки возврата. Повторная очистка необходима: PostgreSQL создаёт компенсирующие проводки при удалении оплат постоя и может признать выручку при обнулении ссылок платежей. Интеграционный тест проверяет именно эти триггеры.

Сохраняются клиенты (включая архивный статус и предпочтения), пользователи, сотрудники, тренеры, лошади, услуги, тарифы, денники, договоры постоя, ветеринарные записи, графики работы персонала и прежний аудит. Рабочие смены персонала WorkShift не удаляются; зарплатные ведомости удаляются.

## Защита закрытых периодов и миграция

Нужна миграция `20261028200000_audited_operational_reset`. Она заменяет только функцию immutable_financial_snapshot: DELETE закрытия/выручки разрешён при наличии специального CashAuditLog от ADMIN, **вставленного в текущей транзакции** (проверка xmin), и локального ключа операции. UPDATE остаётся запрещённым. Один session setting или аудит из прошлой транзакции не разрешает удаление. Триггеры и внешние ключи не отключаются.

`schema.prisma` не меняется. На сервере миграцию применяет штатный `prisma migrate deploy` в deploy.sh.

## Интерфейс

Настройки → «Очистка тестовых данных». Вкладка и компонент доступны только ADMIN. Общие Ant Design Card/Modal/Input/Button/Alert и App message сохраняют текущую тему. Первичный фокус — «Отмена», контрольная фраза точная, кнопка удаления заблокирована до её ввода. Запрос блокирует повтор и закрытие диалога. Ошибка остаётся в диалоге, ввод и ключ сохраняются. Успех инвалидирует весь React Query-кэш (включая dashboard-stats, cashbox, monthly-closing, lessons, memberships, clients и Refine-ресурсы), переводит на `/` и показывает уведомление. Дашборд загружает новые данные при монтировании.

## Проверки

- `npm --prefix backend test`: mock/HTTP-проверки доступа, DTO, порядка FK, снимков аудита, нулевых остатков, сохранения справочников, повторов и отката каждого этапа.
- `npm --prefix backend run test:reset:postgres`: реальная изолированная локальная схема, применение всех миграций, реальные триггеры/FK, откат сброса, нулевые касса/месячный отчёт, сохранение карточек, запрет несанкционированного обхода immutable-защиты. При другом локальном порте: `OPERATIONAL_RESET_TEST_PORT=5432`. Боевые схемы runner не принимает.
- `npx playwright test --project=operational-reset` из frontend: 1280px/375px, точное подтверждение, клавиатура/Escape/восстановление фокуса, ошибка/повтор с тем же ключом, блокировка при загрузке, переход на нулевой дашборд, отсутствие кнопки у менеджера.
