# Быстрый постой

Компонент `src/pages/boarding-contracts/quick.tsx` используется в модальных карточках лошади и денника. Действия доступны ADMIN и MANAGER; TRAINER видит карточку без кнопок изменения.

- При заселении исходная лошадь или денник зафиксированы. Дата и время по умолчанию — текущие в часовом поясе клуба (`schedule/time.ts`), независимо от часового пояса браузера.
- `GET /boarding-contracts/availability?startsAt=<ISO>` возвращает допустимых лошадей и денники для бессрочного договора. Занятость учитывает ACTIVE, SUSPENDED и будущие брони; закрытые денники исключаются.
- «Лошадь клуба» включена по умолчанию, если последний договор выбранной лошади не содержит клиента. Отдельного поля юридического владельца у лошади нет: последний договор служит подсказкой, режим можно изменить вручную. Для выбора из карточки денника подсказка возвращается в `availability.ownerClientId`.
- Клубный постой сохраняется с `clientId: null` и ставкой 0; поля клиента и стоимости скрыты. Сервер принудительно обнуляет ставку и не создаёт платежи; ручной платёж с основанием клубного размещения отклоняется. Частный постой требует клиента и явной ставки. Поиск клиента поддерживает имя и телефон. Существующие частные договоры и платежи сохраняются при миграции.
- Заселение использует существующий `POST /boarding-contracts` со статусом ACTIVE. Сервер повторно проверяет пересечения в транзакции. При конфликте форма сохраняет введённые значения и обновляет доступные варианты.
- Освобождение после подтверждения вызывает `POST /boarding-contracts/:id/terminate`. Договор становится TERMINATED с текущим временем окончания; стороны, стоимость и платежи сохраняются. Повторный запрос не меняет время завершения.
- После изменения инвалидируются `horses`, `stalls`, `boarding-contracts`, `clients`, `payments`, включая открытую карточку. Повторная отправка блокируется. Ошибки остаются видимыми, загрузку вариантов можно повторить.
- Вложенная модалка открывается после готовности карточки; отмена возвращает фокус. Списки закреплены внутри модалки, её содержимое прокручивается, кнопки доступны на узком экране. Панели даты и времени располагаются вертикально на мобильных устройствах.

## Кормление

`Horse.feedingNotes` — необязательный текст до 5000 символов. Он доступен в карточке всем ролям, имеющим доступ к лошадям; редактирование — ADMIN/MANAGER через существующий `PATCH /horses/:id`. Блок `horses/feeding.tsx` сохраняет переносы строк, пустое значение очищает рацион. Ошибка сохраняет черновик, отмена возвращает прежний текст; после сохранения инвалидируется кэш лошадей. Поле также доступно в полной форме лошади.

## Развёртывание и проверки

Перед запуском нового бэкенда применить миграции из каталога `backend`: `npx prisma migrate deploy`, затем выполнить `npx prisma generate` и сборку. Миграция `20261008180000_club_boarding_feeding` делает клиента постоя nullable, добавляет кормление и ограничение нулевой ставки для клубного размещения. Автоматически к рабочей базе миграция не применяется.

Браузерные проверки: `e2e/quick-boarding.spec.ts` (мок API, 320/1280 px, клубный/частный постой, кормление, клавиатура, ошибки, роли, даты). Серверные проверки: `backend/test/boarding-contracts.test.cjs`, `backend/test/horse-feeding.test.cjs`.
