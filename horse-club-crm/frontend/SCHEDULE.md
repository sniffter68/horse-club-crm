# Расписание

Маршрут `/schedule` загружает FullCalendar отдельным модулем. Неделя и день показывают часы работы из `/settings/club-schedule`; выходной скрыт (0 — воскресенье). Диапазон запросов `/lessons` и время создания передаются как UTC ISO. Фильтры `trainerId` и `horseId` применяет сервер.

`VITE_CLUB_TIME_ZONE` по умолчанию `Europe/Moscow` и должен совпадать с `CLUB_TIME_ZONE` бэкенда. Для FullCalendar 6 подключён Luxon-плагин: отображение и ввод не зависят от часового пояса компьютера. Неоднозначный или несуществующий локальный момент не отправляется.

ADMIN/MANAGER создают занятие кнопкой или выбором слота/интервала. Выбор услуги задаёт длительность, которую можно изменить. Нагрузка запрашивается для выбранных лошади и клубной даты. Сервер окончательно проверяет пересечения, рабочее время и нагрузку; сообщение HTTP 409 показывается в модалке, заполненные поля сохраняются. Запросы чтения отменяются при смене параметров и уходе со страницы.

Карточка содержит участников, тренера, лошадь, услугу и время. Статусы меняются через PATCH; отмена требует подтверждения, отменённое занятие нельзя перевести в другой статус. ADMIN/MANAGER управляют занятиями; TRAINER просматривает расписание и нагрузку согласно правам API. Финансовые и медицинские поля в расписании не выводятся.

## Суточная нагрузка и перенос

`GET /horses/workload?date=YYYY-MM-DD` возвращает все лошади, включая свободных: `horseId`, `horseName`, `currentWorkloadMinutes`, `maxDailyWorkloadMinutes`, `status` (`AVAILABLE`, `AT_LIMIT`, `OVERLOADED`, `UNAVAILABLE`). Запрос доступен ADMIN/MANAGER/TRAINER. Расчёт использует рабочий день в часовом поясе клуба, исключает CANCELLED и считает каждую лошадь один раз на групповое занятие. Изменение даты календаря обновляет выбранный день; в неделе бейджи получают данные для соответствующих дат занятий независимо от фильтров расписания.

В форме дата нагрузки следует за временем начала. Селектор показывает использованные минуты и лимит; предупреждение показывает сумму после сохранения. При неизвестной нагрузке выбранной лошади, загрузке, недоступности или превышении лимита сохранение блокируется. Занятие без клубной лошади не зависит от загрузки нагрузки. Равенство лимиту допускается. Запросы отменяются при смене даты; устаревшие ответы не отображаются.

«Перенести занятие» доступно ADMIN/MANAGER только для SCHEDULED. `PATCH /lessons/:id/reschedule` принимает `startTime` и `durationMinutes`; участники, лошади, услуга, тренер, манеж, оплаты и леджер сохраняются. Для предварительной нагрузки передаётся `excludeLessonId`, поэтому исходное занятие не считается повторно. Сервер в Serializable-транзакции заново проверяет рабочее время, пересечения, доступность лошадей/манежа, срок абонементов и нагрузку всех назначенных лошадей. Обхода суточного лимита нет.

Браузерные регрессии: `e2e/horse-workload.spec.ts` (320/768/1280 px, предел нагрузки, перенос, смена даты, загрузка, ошибки/повтор, пустое состояние). Backend-регрессии: `backend/test/horse-workload-display.test.cjs`.

Каталоги для выбора загружаются страницами по 100 записей до `x-total-count`; при ошибке загрузки создание блокируется, доступна кнопка «Обновить». Ошибка 401 передаётся обработчику Refine и сбрасывает сессию.

## Проверка

- `npm run build`, `npm run lint`, `npm test`.
- `npm run test:e2e` — реальный API на 3000 и Vite на 5173, пользователь `admin@test.ru` из dev-сида. Сценарий расписания создаёт собственные каталоги, бронирование, проверяет время UTC, нагрузку, три смены статуса, фильтр и вид дня; контролирует `pageerror`/`console.error`. Удаляет только собственные записи через Prisma, поскольку DELETE занятия в API отсутствует.
- `npm run test:e2e:mock` — дополнительно проверяет выбор слота, сохранение формы после 409 и выход при 401 запроса расписания.

Скриншот реального сценария: `e2e-schedule.png`. Тесты времени: `src/pages/schedule/time.test.ts`.
