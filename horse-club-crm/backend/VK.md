# VK: привязка и доставка уведомлений

## Запуск

1. Применить миграции: из `backend` выполнить `npx prisma migrate deploy`, затем `npm run build`.
2. Задать `VK_COMMUNITY_TOKEN` (токен сообщества с доступом к сообщениям), `VK_CONFIRMATION_CODE` и при необходимости `VK_SECRET_KEY`. Callback: `POST /api/vk-bot/callback`. В настройках Callback API сообщества включить событие `message_new`. `VK_GROUP_ID` нужен для ссылок на сообщество и старого callback, но не блокирует новый адрес. `VK_BOT_TOKEN` поддерживается как резервное имя токена.
3. В разделе «Пользователи» администратор задаёт числовой VK ID для аккаунтов ADMIN, которые получают заявки. Получатель должен разрешить сообщения сообщества.
4. Для клиентов и тренеров ADMIN/MANAGER выдаёт код в соответствующем списке. Бот доступен по ссылке `https://vk.me/club<VK_GROUP_ID>`.

Новый callback возвращает код подтверждения как `text/plain` без проверки секрета для `confirmation`. Для остальных событий заданный `VK_SECRET_KEY` должен совпадать с `secret` в JSON; несовпадение возвращает 403. Без настроенного секрета проверка пропускается. Входящие сообщения и нажатия кнопок получают немедленный ответ `ok`, обработка продолжается асинхронно; ошибки фиксируются без вывода токенов и текста сообщений. Остальные события получают `ok`.

«Начать» и «Привет» отправляют приветствие через `messages.send` с API `5.199`; ответ не требует привязки профиля или обращения к БД. Стабильный `random_id` берётся из `event_id` либо ID сообщения; если оба отсутствуют, используется новый UUID. Недоступность VK не меняет HTTP-подтверждение события. Незавершённая асинхронная обработка может потеряться при остановке процесса; отдельной персистентной очереди входящих callback нет.

Старый `POST /api/vk/callback` сохранён для уже настроенных интеграций: требует `VK_SECRET_KEY` и совпадающий `VK_GROUP_ID`, допускает секрет в заголовке и дожидается обработки события. Для нового подключения используйте `/api/vk-bot/callback`.

## Привязка

- Код из четырёх цифр действует 5 минут. Повторная выдача отзывает предыдущие коды профиля; в БД сохраняется SHA-256.
- Ввод кода или `/start КОД` запускает привязку и запрашивает подтверждение телефона. Завершение: `привязать +79991234567 КОД` или `/start +79991234567 КОД`. Проверка телефона сохранена из прежнего протокола; одного короткого кода недостаточно для доступа к чужому профилю.
- Старые 32-значные коды поддерживаются до окончания срока действия.
- Не более 5 попыток на VK-пользователя за 15 минут в одном процессе. При горизонтальном масштабировании ограничитель необходимо вынести в общее хранилище.
- Отвязка очищает VK ID, отзывает коды и удаляет ожидающие персональные уведомления. Уже отправленное или находящееся в сетевом запросе сообщение отозвать невозможно.
- CLIENT: «Мой баланс», «Мои тренировки». TRAINER: «Расписание на сегодня». Даты отображаются в `CLUB_TIME_ZONE` (по умолчанию Europe/Moscow).
- «Мой баланс» показывает название `Membership.title`, затем `PricingPlan.name` или «Абонемент», остаток занятий и дату окончания без времени. UUID в ответ не включаются. «Мои тренировки» показывает дату с днём недели, время клуба, лошадь, тренера и манеж из `Lesson.arena`, если он указан. Обе команды сохраняют страницы по 10 записей и кнопку «Далее»; пустые списки получают отдельное понятное сообщение.

## Главное меню, контакты и помощь

Клиент получает три ряда reply-клавиатуры: «📅 Мои тренировки» / «💳 Мой баланс», «ℹ️ О клубе» / «📖 Памятка всадника», «💬 Связаться с администратором». Гостям дополнительно доступны привязка профиля и первичная заявка; тренеры сохраняют кнопку расписания вместо клиентских команд. Общедоступные контакты, памятка и вызов администратора доступны также без привязки.

Команды принимаются с эмодзи и без них, включая «о клубе», «контакты», «памятка», «памятка всадника», «помощь», «администратор», «позвать администратора» и «связаться с администратором». «Помощь» вызывает администратора. Payload кнопок использует `about`, `guide`, `help`; клиентские payload `bookings` и `balance` сохранены.

Тексты настраиваются в `vk-bot.config.ts` через `VK_CLUB_NAME`, `VK_CLUB_ADDRESS`, `VK_CLUB_HOURS`, `VK_CLUB_PHONE`, `VK_CLUB_MAP_URL`. Без настроенного адреса, телефона или карты бот предлагает уточнить их у администратора, без вымышленных контактов. `VK_RIDER_GUIDE` позволяет заменить памятку целиком (`\n` превращается в перенос строки). Эти переменные передаются в production-контейнер через Compose; после изменения `.env.production` пересоздайте backend.

Вызов администратора всегда отправляет в текущий диалог клиента подтверждение: «💬 Мы передали ваш запрос администратору клуба!\nСпециалист свяжется с вами в этом диалоге в ближайшее время. 🐎». Событие фиксируется в журнале как `vk_help_requested` с VK ID, ID события и временем, даже если получатель не настроен или БД недоступна.

Служебная карточка с именем, профилем VK, временем клуба и инструкцией оператору ставится в DB-очередь `VkNotification` только для отдельного `VK_ADMIN_PEER_ID`. Если он не задан, некорректен или совпадает с диалогом клиента, карточка не отправляется, причина логируется как `vk_help_not_queued`. CRM-получатели ADMIN для этой команды не используются; правила уведомлений о первичных заявках сохранены. Ошибка записи в очередь также логируется и не мешает подтверждению клиенту.

Карточка содержит профиль клиента и прямую ссылку `https://vk.com/gim{groupId}?sel={userId}` для открытия диалога от имени сообщества. ID берётся из `VK_GROUP_ID`, пробелы и знак минус удаляются. При отсутствующем или некорректном ID вместо прямой ссылки используется профиль клиента; дополнительных запросов к VK для определения группы нет.

Повторная доставка одного callback не создаёт дубликатов; новый запрос с другим `event_id` — отдельное обращение. Доставка администратору асинхронная с повторными попытками. Администратор отвечает вручную в сообщениях сообщества. Проверки ответа клиенту, отдельной отправки карточки через очередь, совпадающего/отсутствующего получателя и ошибок БД: `test/vk-bot-menu.test.cjs`.

## Доставка уведомлений

Заявка, создание/добавление участника, перенос и отмена занятия записывают уведомления в `VkNotification` в той же транзакции. Транспорт проверяет очередь каждую секунду; ошибка VK сохраняет сообщение для повтора и не откатывает занятие/заявку. Ключ проводки и стабильный `random_id` защищают от повторов. Повторный перенос после возврата на старое время считается отдельным изменением.

Создание через `POST /lessons` или `POST /bookings` сразу сохраняет запланированное занятие (`SCHEDULED` / `scheduled`); отдельного статуса `confirmed` в схеме нет. Тренеру отправляется персональная карточка с датой/временем клуба, именами и телефонами записанных участников, их лошадьми и типом занятия. Клиент получает собственное подтверждение с тренером, своей лошадью и просьбой приехать за 15 минут, без данных других участников. При добавлении в групповое занятие уведомляются тренер и только новые участники. Переносы и отмены сохраняют прежние уведомления.

Получатели берутся из `Trainer.vkUserId` и `Client.vkUserId`; без привязанного VK ID сообщение пропускается независимо от источника лида. Заявка из VK сама по себе не заменяет существующую привязку профиля с проверкой телефона. Тип занятия берётся из `Service.title/name` либо русскоязычного названия `Booking.serviceType`. У `Lesson`/`Booking` нет поля примечания: в карточке выводится «не указано». Назначенная лошадь берётся из записи, отдельного каталога бот не показывает.

Ошибка отправки, в том числе VK 901, даёт warn «Не удалось отправить VK-уведомление для userId: …» с кодом ошибки, ID уведомления и номером попытки. Следующий получатель продолжает обрабатываться; повторные попытки используют существующую задержку до одного часа. Проверки карточек, часового пояса, приватности групповых записей и ошибок API: `test/vk-training-notifications.test.cjs`, `test/vk-bot-scenarios.test.cjs`.

Повторы используют экспоненциальную задержку от 10 секунд до 1 часа, чтобы недоступные получатели не блокировали новые уведомления.

`VK_ADMIN_PEER_ID` остаётся дополнительным получателем для совместимости; совпадающие ID дедуплицируются. Удалите эту настройку, если доставка должна управляться только через аккаунты ADMIN.

Проверки без реальных сообщений: `npm test` в backend; `npm run test:e2e:mock` в frontend с запущенным Vite. Тесты используют подставной транспорт VK и API.
