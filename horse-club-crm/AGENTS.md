# Архитектурный регламент проекта Horse Club CRM (crm.horseclub68.ru)

Этот документ является обязательной постоянной инструкцией для всех AI-агентов (Codex, Cursor, Copilot) при выполнении любых задач в репозитории.

## 1. Стек и структура проекта
- Монорепозиторий:
  - `backend/`: NestJS, Prisma ORM, PostgreSQL, class-validator, Jest.
  - `frontend/`: React, TypeScript, Tailwind CSS / UI-компоненты, Playwright (E2E).
  - `docs/`: архитектурная документация, changelog, отчеты тестов.
- Рабочая среда: Windows (PowerShell) локально, Ubuntu (Docker) на VDS (`/opt/horse-club-crm/horse-club-crm`).
- Локальная база PostgreSQL может быть недоступна: mock-тесты и браузерные сценарии обязательны, `prisma migrate deploy` выполняется на сервере.

## 2. Железные правила бэкенда (NestJS + Prisma)
1. **Query DTO**: все числовые параметры (`offset`, `limit` и др.) обязательно оборачивать в `@Type(() => Number)`.
2. **Опциональные UUID / Enum**: пустые строки `""` обязательно трансформировать в `undefined` до валидации `@IsUUID()` / `@IsEnum()`.
3. **Финансовая целостность и Касса**:
   - Любые списания, выплаты зарплат (`SALARY`) и приемы оплат проводятся ТОЛЬКО через `prisma.$transaction`.
   - Запрещено удаление финансовых записей без аудита (`createdById`, `timestamp`).
4. **Модульность и права (RBAC)**:
   - Контроллеры защищаются через `@RequireModule(...)`.
   - Уровни доступа: `FULL`, `READ_ONLY` (блокировать мутации POST/PATCH/DELETE), `HIDDEN` (403 Forbidden).
   - Администратор (`ADMIN`) всегда имеет `FULL` доступ ко всем модулям.

## 3. Доменные правила конного клуба
- Даты, расписание и смены всегда считаются по таймзоне `Europe/Moscow`.
- Лошади: учет лимитов нагрузки в минутах, запрет записи при статусах `TREATMENT` или `QUARANTINE`.
- Карта денников: проверка соседства (предупреждение при постановке жеребца рядом с кобылой или другим жеребцом).

## 4. Требования к фронтенду и дизайну
- Использовать аккуратные Slide-over Drawers (боковые шторки) для создания/редактирования сущностей, сохраняя контекст экрана.
- Цвета статусов: мягкие пастельные бейджи (Soft Badges).
- При `READ_ONLY` скрывать или блокировать кнопки мутаций (`+ Создать`, `Выплатить`, `Удалить`).
- Перед отправкой запросов проверять валидность UUID параметров.

## 5. Протокол сдачи задачи
Перед завершением задачи агент ОБЯЗАН:
1. Запустить сборку `npm run build` в `backend` и `frontend`.
2. Прогнать линтеры и тесты (`npm test`).
3. Предоставить краткий отчет: что сделано, какие тесты прошли, требуется ли применение миграции Prisma.
## Критерии готовности (Definition of Done)
Перед отправкой финального ответа агент обязан:
1. Запустить проверку типов TypeScript: `npm run typecheck` (или `tsc --noEmit`).
2. Запустить линтер и убедиться в отсутствии ошибок: `npm run lint`.
3. Запустить сборку обоих проектов: `npm run build` в `backend/` и `frontend/`.
4. Запустить релевантные тесты: `npm test`.
5. При наличии изменений в схеме БД — убедиться, что сгенерирован Prisma Client (`npx prisma generate`).
