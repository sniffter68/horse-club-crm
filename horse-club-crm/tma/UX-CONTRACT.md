# Telegram Mini App: контракт поведения

Визуальный источник: [DESIGN.md](DESIGN.md). Основание: задача владельца от 08.11.2026, общие правила репозитория и существующий LessonsService.

## Canonical UI Map

| Capability | Canonical owner | Source of truth | Allowed variants | Verification |
| --- | --- | --- | --- | --- |
| Select/Listbox | `App.tsx` | Нативный select | Системный popup | `e2e/booking.spec.ts` |
| Date | `App.tsx` | Нативный date | Ближайшие 30 дней | `e2e/booking.spec.ts` |
| Form | `App.tsx` | noValidate, inline ошибки | Телефон +7 и согласие | `e2e/booking.spec.ts` |

| CRUD | `api.ts`, `MyBookings` | Клиентские маршруты | Создание, история, запрос отмены | `e2e/booking.spec.ts` |

Каталог → дата/время → оформление → успех → мои записи. BackButton возвращает на предыдущий шаг, из истории/успеха — в каталог. В оформлении Telegram предупреждает перед закрытием WebView. Имя и username — из Telegram, доверенной идентичностью является только серверная проверка initData.

Отправка блокируется ref и состоянием busy. После сетевой ошибки повтор использует тот же requestId, сервер возвращает существующую запись. Смена слота начинает новое оформление. При 401 пользователь повторно открывает WebApp через бота. Данные не сохраняются в браузерном storage. История — по 20 строк с «Загрузить ещё».

Ошибка загрузки имеет повтор; ошибка отправки сохраняет телефон и согласие. Старые запросы слотов отменяются. Пустое расписание предлагает другую дату. Успех содержит время, тренера и адрес. Запрос отмены требует inline подтверждения; сохраняет резервацию и финансы до решения администратора.

По задаче владельца от 09.11.2026 экран `my-bookings` открывается из шапки и карточки успеха. Запросы передают `Authorization: tma ${initData}`; сервер сохраняет совместимость с `X-Telegram-Init-Data`, проверяя подпись до определения клиента. История исключает уроки с `deletedAt`, сохраняет записи без урока и сортировку по времени убыванию. Список разделяет предстоящие и прошедшие тренировки; пустой список предлагает «Записаться». Отсутствующие тренер, услуга или дата не прерывают рендер. Успех использует выбранные данные при отсутствии связей в ответе и предлагает «Мои записи» и «Новая запись».

Права: TMA имеет только клиентские маршруты с TelegramAuthGuard и проверкой включённого SCHEDULE. Staff FULL/READ_ONLY/HIDDEN не выдаются посетителям и продолжают действовать на CRM. Все операции с записями ограничены clientId из подписи.

По задаче владельца от 09.11.2026 при оформлении номер нормализуется; существующая карточка без Telegram ID привязывается к текущему Telegram-пользователю. Номер другого Telegram-аккаунта отклоняется. Нативная кнопка запрашивает контакт через SDK; отказ, отсутствие контакта или неподдерживаемая версия оставляют ручной ввод. Текст «Номер получен из Telegram» описывает источник заполнения, не серверную проверку владения. Согласие хранится с версией и timestamp на Booking; юридические документы переиспользуются с действующего лендинга.

Проверки: backend mock/HTTP security tests, browser suite `e2e/booking.spec.ts`, узкая ширина, тема Telegram, native MainButton/BackButton, retry/double click/empty/error. Нативные системные date/select остаются ответственностью ОС; проверка реального Telegram на устройстве нужна при выпуске.
